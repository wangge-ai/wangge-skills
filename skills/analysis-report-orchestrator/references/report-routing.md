# Report Routing

## Routing order

决策任务优先，业务对象其次，报告标题只作为辅助信号。

## Decision-task axis

| 类型 | 核心问题 | 常见报告 | 默认分析方向 |
|---|---|---|---|
| 监测型 | 现在表现如何 | 日报、周报、月报、经营看板 | 指标、趋势、结构和目标差距 |
| 诊断型 | 为什么出现问题 | 流量下降、滞销、ROI 异常 | 问题树、因子拆解和根因验证 |
| 洞察型 | 有什么规律和需求 | 用户研究、评价分析、趋势洞察 | 分类编码、归纳和深层需求 |
| 比较型 | 谁更好、差异在哪 | 竞品、平台、渠道、方案对比 | 统一口径、对标和差异边界 |
| 评估型 | 是否达标、是否值得 | 活动、供应商、项目评估 | 标准、权重、证据和评分 |
| 决策型 | 应该选择什么 | 新品、选品、投放和渠道决策 | 成本、收益、风险和备选方案 |
| 预测型 | 接下来可能怎样 | 销量、库存和趋势预测 | 历史基线、情景和预测区间 |
| 规划型 | 下一步怎样推进 | 增长、营销、渠道和整改计划 | 目标差距、路径、资源和节奏 |
| 复盘型 | 做得怎样、如何改进 | 大促、项目、新品和活动复盘 | 目标、结果、原因和行动闭环 |

## Business-object axis

| 业务对象 | 分析范围 |
|---|---|
| 经营 | GMV、订单、转化、客单、利润和增长 |
| 市场 | 类目规模、趋势、机会、区域和人群 |
| 竞品 | 商品、价格、卖点、页面、评价和策略 |
| 商品 | SKU、定价、生命周期、新品和滞销品 |
| 用户 | 用户分层、VOC、评价、问大家和客服会话 |
| 流量营销 | 搜索、推荐、广告、活动、渠道和 ROI |
| 内容视觉 | 主图、详情页、短视频、直播和品牌内容 |
| 供应链 | 库存、补货、交付、供应商和售后 |
| 财务 | 成本、毛利、净利、现金流和保本点 |
| 组织项目 | 团队效率、项目进度、活动执行和复盘 |

## Mixed reports

识别一个主任务和零个或多个子模块。只保留一个执行摘要，各模块分别选模，最后统一行动优先级。

例如，“抖音新品投放三周后 ROI 下降分析”可路由为“诊断型 × 流量营销 × 新品阶段”。若同时要求月度表现、流量诊断和下月计划，则将监测型经营报告作为主任务，并将诊断型流量分析和规划型增长方案作为子模块。

## Route result

- 主决策任务
- 业务对象
- 子任务
- 报告深度
- 推荐模型
- 报告结构
- 资料状态
- 生成状态
