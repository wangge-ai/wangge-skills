# Evidence and Quality Rules

## 报告任务卡

| 字段 | 内容 |
|---|---|
| 报告目的 | 需要解决的具体问题 |
| 决策对象 | 报告将支持的决定 |
| 阅读者 | 运营、管理者、产品、供应链或客户 |
| 分析对象 | 店铺、商品、用户、竞品、活动或项目 |
| 时间范围 | 日、周、月、活动期或历史区间 |
| 比较基准 | 环比、同比、目标值、行业或竞品 |
| 数据来源 | 表格、平台后台、截图、网页、访谈或描述 |
| 输出要求 | 简报、标准报告、深度报告、表格或演示文稿 |

即使用户没有明确报告名称，只要决策目标、对象和范围可以识别，仍可继续路由。

## 六类证据状态

| 状态 | 定义 |
|---|---|
| 已验证事实 | 来源明确并可核对 |
| 计算结果 | 根据已知数据计算，保留公式和口径 |
| 外部资料 | 来自公开网页、行业资料或第三方报告 |
| 分析推断 | 根据事实形成的解释，不等于事实 |
| 待验证假设 | 当前证据不足，需要进一步验证 |
| 数据缺失 | 支持判断所需但未提供的信息 |

## 六个资料质量维度

对每项关键资料进行质量评分并检查：

1. 来源是否可追溯；
2. 时间是否适用于本次分析；
3. 指标口径是否一致；
4. 样本是否具有代表性；
5. 不同数据能否直接比较；
6. 资料是否足以支持目标结论。

局部数据只能支持局部结论。截图只能支持截图可见内容。定性材料不能生成虚假比例。

## 绿黄红生成状态

### 绿色：方案后自动继续

同时满足报告目的、阅读者和范围明确，核心数据基本齐全，主要来源可追溯，关键指标口径没有明显冲突，并且属于低风险常规报告。

### 黄色：等待用户确认

当缺少部分比较数据、样本有限、只能支持局部结论、指标口径不完全一致、同时包含多个报告任务，或涉及预测、因果判断、重要经营决策时，先输出：

1. 报告类型判断；
2. 推荐模型组合；
3. 可以回答的问题；
4. 暂时不能回答的问题；
5. 缺失资料；
6. 报告目录；
7. 预计结论可信度。

### 红色：停止正文

出现下列任一情况时停止正文：无法确认要解决的问题；没有任何可验证资料；核心数据矛盾且无法识别口径；要求因果结论但只有相关性资料；要求精确预测却没有历史数据或基础假设；要求整体市场结论却只有少量个案；或资料不足以支持重大财务、法律、合规判断。

红色状态只输出：无法可靠生成的原因、最小补充资料清单、可替代的有限分析方案。

## 第二阶段统一正文契约

### 执行摘要

说明最重要的结论、结论依据、建议行动、可信度和限制。

### 任务与范围

说明报告目标、分析对象、时间范围、数据范围、指标口径和不包含的内容。

### 数据与方法

说明数据和资料来源、数据处理或计算方法、使用的分析模型、模型选择原因，以及数据缺失和偏差。模型必须对应实际分析产出，不能只在方法章节中列名。

### 关键发现

每项核心发现使用：

```markdown
### 发现：结论性标题

- 事实：
- 证据：
- 解释：
- 边界：
```

### 原因或机制分析

按报告类型加载相应的分析产出：指标变化和目标差距、问题树和原因验证、样本规律和深层需求、统一维度下的差异、标准得分与证据、方案收益成本与风险、趋势假设与情景区间、目标路径资源与节奏，或目标结果原因与改进。

### 结论

结论必须回应报告目标、追溯到前文证据、区分确定结论和待验证判断、按业务影响排序，并避免重复分析过程。

### 行动建议

| 字段 | 要求 |
|---|---|
| 动作 | 具体做什么 |
| 依据 | 对应哪项发现 |
| 优先级 | 高、中、低 |
| 负责人 | 谁执行；未知则标记待指定 |
| 时间 | 何时完成；未知则标记待指定 |
| 指标 | 如何判断有效 |
| 风险 | 可能出现的问题 |
| 后手 | 无效时如何调整 |

### 风险与未知项

单独列出数据限制、样本偏差、口径冲突、外部变量、尚未验证的假设，以及可能推翻当前结论的新证据。

### 附录

按需包含数据来源清单、指标定义、计算公式、样本说明、详细表格和外部资料链接。

## 三种报告深度

| 级别 | 适用情况 | 输出结构 |
|---|---|---|
| 简报 | 日常汇报、快速决策 | 摘要、发现、建议和风险 |
| 标准报告 | 周月报、竞品、用户和活动分析 | 完整正文契约 |
| 深度报告 | 战略、新品、重大诊断和研究 | 完整契约、多模型交叉验证和附录 |

默认生成标准报告。用户明确要求快速查看时使用简报；涉及重大投入、长期规划或复杂证据时升级为深度报告。

## 九条全局报告规则

1. **结论可追溯：**每条核心结论至少对应一项证据；没有证据的内容只能标记为推断、假设或待验证项。
2. **比较同口径：**时间范围、平台定义、商品范围、价格状态和样本范围不一致时，不能直接排序或计算差距。
3. **比例有分母：**使用“多数”“明显提升”“差评集中”等表述时，应说明样本数、占比和范围；没有分母时使用定性表述。
4. **相关不等于因果：**指标同步变化、时间同时发生或用户共同提及，不能直接证明因果关系。
5. **建议对应发现：**每项建议必须能够指回具体发现，不能生成与报告证据无关的通用建议。
6. **建议可验证：**“加强运营”“优化页面”“提高质量”不是完整建议；建议必须包含具体动作和验证指标。
7. **未知项保留：**不能为了让报告完整而填补未知数据；无法判断时，说明需要补充的证据。
8. **报告服务决策：**背景、行业常识和模型介绍不能占据主体；报告重点是判断、证据、行动和风险。
9. **禁止自动编造：**不得编造行业平均值、市场规模、竞品销量、用户画像比例、未提供的成本、未验证的转化原因、虚构访谈评价案例，或没有数据支持的效果幅度。
