# Analysis Report Orchestrator

## Routing contract

- 决策任务优先，业务对象其次，报告标题只作为辅助信号。
- 先建立报告任务卡和资料审计，再选择模型。
- 混合任务选一个主任务，其余作为子模块；无法归类时使用开放式报告流程。
- 模型默认使用 2–3 个，每个模型必须对应实际分析产出。
- 区分事实、计算结果、外部资料、分析推断、待验证假设和数据缺失。

## Stage one（第一阶段）

使用 `assets/task-card-template.md` 和 `assets/analysis-plan-template.md`。

1. 读取全部资料和限制，识别决策目标、阅读者、对象、时间、范围和比较基准。
2. 输出任务卡、资料审计、分析方案、模型选择和报告深度（简报、标准报告或深度报告）。
3. 绿色：资料充分且低风险，输出方案后可继续第二阶段。
4. 黄色：局部、混合、口径冲突、预测、因果或重要经营决策，等待确认。
5. 红色：目标不清、完全无证据、支持目标结论的核心变量明确缺失或结论要求超出资料，停止正文。
6. 已有局部证据但口径冲突可通过补齐或确认解决时，必须判为黄色，不得仅因当前无法直接比较而判为红色。
7. 少量样本推断整个总体并要求确定比例，或同一核心经营指标的来源差异足以改变正式报告结论且口径说明缺失时，必须判为红色。
8. 混合任务任一子模块仍有关键约束未确定时，必须判为黄色，即使主任务资料完整也不得生成正文。

### 强制输出契约

- 每次都按 `references/evidence-and-quality-rules.md` 的“第一阶段输出契约”完整输出 `## 报告任务识别`、`## 资料审计`、`## 分析方案`、`## 生成状态` 四个标题，不得省略、改名或改成加粗段落；精简答复和红色状态也不例外。
- 第一阶段以下三行必须逐字复制完整格式，行首的 `- ` 也是必需内容；不得缩进、加粗、添加标点、后缀或改写。只替换尖括号内选项，并按绿色→自动生成、黄色→等待确认、红色→暂停正文：
```text
- 报告类型：<标准主类型>
- 状态：<绿色 / 黄色 / 红色>
- 处理方式：<自动生成 / 等待确认 / 暂停正文>
```
- 混合任务还必须逐字复制以下完整格式，并替换尖括号内内容：
```text
- 主任务：<标准主类型及任务>
- 子模块：<其他任务类型及任务>
```
- “报告类型”必须从 `references/report-routing.md` 的决策任务轴选择一个标准主类型：监测型、诊断型、洞察型、比较型、评估型、决策型、预测型、规划型或复盘型。资料审计、来源对账和证据比较只是前置步骤，不得取代最终决策任务；例如正式经营报告仍为监测型。混合任务必须显式写出 `主任务` 和 `子模块`；其他类型写为子模块，不用自定义名称替代主类型。用截图判断页面、体系或对象表现属于评估型；只有在已有异常结果并要求解释原因时才路由为诊断型。
- 用户明确说资料“已提供”“已有”或要求“根据/基于某资料”分析时，按该陈述审计该资料已提供；除非陈述本身说明缺失、冲突或局部范围，不得仅因当前提示未展开数值、资料未以内联内容出现或工作区未找到附件而改判为资料缺失，也不得因此编造具体数值。
- 资料审计和限制必须原样保留任务中的关键证据名称、数值与单位（例如 `8条`、`30%`、`结算价`），不得因改写或空格规范化而丢失精确证据条件。
- 绿色状态在四个标题后继续第二阶段正文；黄色和红色状态在 `## 生成状态` 后停止，不得输出 `## 执行摘要`、`## 关键发现` 或其他正式报告正文。

## Stage two（第二阶段）

进入模板前先检查实际数值或内容是否在当前提示或会话中可见。若用户只声明资料存在但未展示内容，绿色正文必须定义为“条件分析稿”：事实只列已声明的资料，`## 关键发现` 只写“若条件成立 → 如何判断”，结论只写公式、决策规则和明确回填点；机制项只能写无序验证清单或排序公式，不能给固定排查顺序；行动表只写触发条件、条件动作和验证指标，每行优先级一律写 `待回填`。不得声称已观察到变化方向、原因排序、最可能机制、确定性发现或固定行动优先级；在前后添加“条件分析稿”“数值未展开”等免责声明不能抵消违规。此门禁适用于全部报告类型。

使用 `assets/report-template.md`，根据任务选择简报、标准报告或深度报告。完成后：

1. 确认每条核心结论对应可见证据，并逐段复查执行摘要、关键发现、机制分析、结论和行动表是否通过上述内容可见性门禁。
   - 内容不可见时，正文任何位置出现“最重要”“最关键”“主要原因”“优先顺序”等固定排序即不合格；行动表优先级数据格出现 `高`、`中` 或 `低` 即不合格，必须全部改为 `待回填`。标题、方法性工作和资料回填动作也没有例外。
2. 确认事实、推断和假设分离。
3. 确认建议对应发现并包含验证指标。
4. 运行 `scripts/validate_report.py` 进行结构验证。
5. 完成 100 分语义质量复核，低于 80 分不交付。

## Required references

- 路由任务时读取 `references/report-routing.md`。
- 审计证据和生成正文时读取 `references/evidence-and-quality-rules.md`。
- 选择模型时读取 `references/model-selector.md`。
- 电商专项报告读取 `references/ecommerce-report-recipes.md`。
- 未知、非电商或无法稳定分类的报告读取 `references/open-report-fallback.md`。

## Non-negotiable boundaries

- 不把推断或假设写成事实，不补写未提供或未验证的数据。
- 比较必须同口径，比例必须说明分母；相关性不能直接写成因果关系。
- 核心结论必须可以追溯证据；建议必须对应发现，并包含验证指标。
- 红色状态不得生成正式报告正文。
- 第一阶段以用户任务对资料状态的陈述为准，不重新用附件发现结果推翻该陈述。任务说“根据一张截图”时必须把该截图记为已有局部证据，并在 `## 生成状态` 写 `状态：黄色`；不得因当前消息未内联图片或工作区没有图片文件而写成红色、声称未收到或要求重新上传。
