# 飞书项目周报助手

## 概述

把"收集证据 → 生成周报 → 更新表格 → 催办消息"这套每周重复的流程标准化，按固定 7 步执行，每步有明确的输入、输出、停止条件和验收清单。

核心原则：**先读后写，未知不补，冲突保留，不覆盖原始资料，不批量发送消息。**

## 触发条件

用户明确要求以下任一操作时触发：
- 生成项目周报 / 跑周报流程
- 更新项目进展 / 项目跟进表
- 生成催办消息 / 风险提醒
- 每周项目汇报 / 项目总结

不触发的场景：
- 只问单个任务状态（直接查表格回答即可）
- 只需要发一条消息（直接用消息能力）
- 与项目周报无关的文档编辑

## 输入项

每次运行前必须确认以下信息，缺失的要问用户，不要猜：

| 输入项 | 说明 | 是否必填 |
|---|---|---|
| 项目名称 | 项目准确名称，用于搜索群聊、文档、表格 | 是 |
| 群聊名称 | 项目群的准确名称 | 是 |
| 统计开始时间 | 本期统计开始日期 | 是 |
| 统计结束时间 | 本期统计截止日期 | 是 |
| 周报文档 | 已有周报文档名称或链接（首次运行则无） | 否 |
| 项目跟进表 | 已有多维表格名称或链接（首次运行则无） | 否 |
| 会议记录位置 | 会议纪要所在文件夹或日历 | 否 |

## 固定 7 步流程

### 第 1 步：询问项目信息

**动作**：向用户确认项目名称、群名、统计时间、目标文档。

**输出**：输入项确认清单，缺失的标注"待用户提供"。

**停止条件**：
- 项目名称或群名缺失，且用户无法提供
- 用户明确表示不需要继续

**验收清单**：
- [ ] 项目名称已确认
- [ ] 群聊名称已确认
- [ ] 统计开始时间已确认
- [ ] 统计结束时间已确认
- [ ] 已有周报文档（如有）已确认
- [ ] 已有项目跟进表（如有）已确认

---

### 第 2 步：只读资料并输出证据清单

**动作**：读取时间范围内的群消息、文档更新、表格记录、会议纪要，整理成证据清单。

**输出**：证据清单表格，每条包含来源类型、来源名称、信息时间、内容摘要、原始链接。

**规则**：
- 只读不写，不修改任何原始资料
- 找不到的资料明确标注"未找到"，不编造
- 冲突信息保留两个来源，不自行判断
- 群聊消息没有单独链接时，标注群名和时间范围

**停止条件**：
- 目标群聊或目标表格找不到
- 权限发生变化，无法读取
- 证据数量超过 100 条（可能是范围错了，需要人工确认）

**验收清单**：
- [ ] 群聊消息已读取
- [ ] 文档更新已读取
- [ ] 表格记录已读取
- [ ] 会议记录已读取（或标注未找到）
- [ ] 每条证据都有来源和时间
- [ ] 冲突项已标注
- [ ] 缺失项已标注

---

### 第 3 步：等用户确认后生成飞书周报

**动作**：基于证据清单生成项目周报，先在对话中展示全文，等用户确认后创建飞书文档。

**输出**：
- 对话中展示周报全文（6 部分结构）
- 用户确认后创建飞书文档，返回文档链接

**周报结构（固定 6 部分）**：
1. 项目概述：整体情况、关键数字、总体判断
2. 进度明细：每项任务的名称、状态、负责人、截止时间、进展
3. 风险与阻塞：风险事项、影响范围、需要的支持
4. 下一步计划：下周期要做的事、负责人、时间节点
5. 待确认事项：信息不全、需要人工核实的内容
6. 引用链接：所有引用的原始资料链接

**规则**：
- 所有关键结论必须保留来源链接
- 负责人、截止时间无法确认时标记"待确认"，不编造
- 任务状态只写证据中明确提到的，不根据语气自行推断
- 完成数量和延期数量从证据中现算，不估算
- 不新增证据中没有的业务判断

**停止条件**：
- 用户对周报内容有重大异议，需要重新收集证据
- 关键信息缺失超过 5 项，需要人工补充

**验收清单**：
- [ ] 周报 6 部分结构完整
- [ ] 所有关键结论都有来源链接
- [ ] 待确认事项已明确标注
- [ ] 数字与证据清单一致
- [ ] 没有把计划写成已完成
- [ ] 没有把群成员写成负责人
- [ ] 用户已确认全文

---

### 第 4 步：等用户确认后创建或更新项目多维表格

**动作**：创建或更新项目跟进多维表格，写入任务记录。

**输出**：
- 多维表格链接
- 新增记录数、修改记录数、跳过重复数、待确认数、失败数

**字段定义（10 个）**：
1. 任务名称（文本，必填）
2. 状态（单选：待启动/进行中/已完成/已取消/待确认）
3. 负责人（人员）
4. 截止时间（日期）
5. 优先级（单选：高/中/低）
6. 风险等级（单选：高/中/低/无）
7. 关联文档（超链接）
8. 备注（文本）
9. 创建时间（日期，自动）
10. 最后更新时间（日期，自动）

**视图（3 个）**：
- 全部任务：默认视图
- 进行中：筛选状态=进行中
- 高风险：筛选风险等级=高

**规则**：
- 写入前检查是否已有同名表格，有则追加记录，不重复创建
- 写入前去重，按任务名称匹配，已存在的不重复写入
- 负责人 open_id 无法解析时，状态设为"待确认"，备注写明原因
- 不覆盖已有记录的人工备注
- 只写存储字段，不写公式字段和系统字段
- 只更新有变化的记录，不重新写入没有变化的记录

**停止条件**：
- 表格写入权限不足
- 重复记录超过 10 条（可能是匹配规则有问题）
- 需要删除或覆盖已有记录（高风险，必须人工确认）

**验收清单**：
- [ ] 10 个字段全部创建
- [ ] 3 个视图全部配置
- [ ] 写入前去重完成
- [ ] 人工备注未被覆盖
- [ ] 待确认记录已标注
- [ ] 新增/修改/跳过/失败数量已统计

---

### 第 5 步：生成催办消息草稿

**动作**：从跟进表中筛选延期、即将到期、高风险的任务，为每条生成催办消息草稿。

**输出**：催办消息草稿列表，每条包含接收人、具体事项、当前状态、截止时间、需要确认的动作、文档链接。

**筛选条件（满足任一即可）**：
1. 当前状态为"延期"
2. 截止时间在未来 3 天内且尚未完成
3. 风险等级为"高"

**消息内容要求（6 项）**：
1. 接收人：任务负责人（无法确认时标记"待确认"）
2. 具体事项：任务名称和当前进展
3. 当前状态：延期/即将到期/高风险
4. 截止时间：具体日期
5. 需要对方确认或完成的动作：明确写清楚
6. 对应的文档或表格链接

**规则**：
- 只输出草稿，不自动发送
- 接收人无法确认时标记"待确认"
- 语气直接、礼貌，不虚构项目背景
- 每条消息单独列出，标注序号

**停止条件**：
- 需要发送消息（必须等用户明确确认具体消息后才发）
- 需要批量发送（禁止，必须逐条确认）

**验收清单**：
- [ ] 筛选条件正确应用
- [ ] 每条消息 6 项内容齐全
- [ ] 接收人无法确认的已标注
- [ ] 文档链接已附上
- [ ] 没有自动发送任何消息

---

### 第 6 步：只有在用户明确确认具体消息后才允许发送

**动作**：用户确认某条具体消息后，发送该条消息。每次只发一条，发完等下一次确认。

**输出**：发送结果（接收对象、发送时间、消息链接、执行状态）。

**规则**：
- 发送前必须再次向用户展示最终接收人和完整消息内容
- 等用户回复"确认发送"后才执行
- 每次只发送一条，不批量发送
- 不发送用户未确认的消息
- 不修改文档和表格

**停止条件**：
- 用户未明确确认具体消息
- 接收人无法确认
- 发送权限不足

**验收清单**：
- [ ] 发送前已展示最终接收人和完整内容
- [ ] 用户已明确回复"确认发送"
- [ ] 只发送了确认的那一条
- [ ] 发送结果已返回（接收对象、时间、链接、状态）

---

### 第 7 步：最后汇报新增、修改、跳过、失败和待确认事项

**动作**：汇总整个流程的执行结果，输出最终汇报。

**输出**：最终汇报表格，包含以下字段：

| 类别 | 数量 | 说明 |
|---|---|---|
| 新增记录 | X 条 | 新写入表格的任务 |
| 修改记录 | X 条 | 更新了状态/负责人/截止时间的记录 |
| 跳过记录 | X 条 | 重复或无变化的记录 |
| 失败记录 | X 条 | 写入失败的记录及原因 |
| 待确认事项 | X 项 | 需要人工核实的内容 |
| 催办消息草稿 | X 条 | 已生成未发送的消息 |
| 已发送消息 | X 条 | 用户确认后发送的消息 |
| 引用链接 | X 条 | 周报中引用的原始资料链接 |
| 冲突项 | X 项 | 来源之间说法不一致的内容 |

**附加汇报**：
- 总耗时
- 读取资料数（群消息、文档、表格、会议分别多少）
- 人工确认次数（每一步用户确认了几次）

**验收清单**：
- [ ] 9 类统计数据完整
- [ ] 失败项有原因说明
- [ ] 待确认事项有具体内容
- [ ] 总耗时已统计
- [ ] 读取资料数已分类统计
- [ ] 人工确认次数已统计

## 固定规则（全程适用）

1. **先读后写**：所有写入操作前必须先读取现有内容
2. **未知信息不补写**：负责人、截止时间等无法确认时标记"待确认"，不编造
3. **冲突信息保留来源**：不同来源信息不一致时，保留两个来源和原始内容，不自行判断
4. **不覆盖原始资料**：不修改、不删除、不覆盖用户的原始文档和备注
5. **不批量发送消息**：催办消息必须等用户明确确认具体消息后才发送，每次只发一条
6. **涉及发布、发送、删除、覆盖时必须再次确认**：不能自动执行高风险操作

## 错误处理

- 同一动作失败最多重试 1 次，仍失败就停止并说明原因
- 权限不足时，明确告知用户需要什么权限，不尝试绕过
- 数据格式错误时，列出具体错误行和字段，不自行修改原始数据
- 部分成功时，汇报成功了哪些、失败了哪些，不假装全部成功

## 与其他 Skill 的关系

- 本 Skill 专注项目周报流程，不处理通用文档编辑
- 需要生成 PPT 时，调用幻灯片能力，不在本 Skill 内实现
- 需要做数据分析时，调用数据分析能力，不在本 Skill 内实现
- 需要定时运行时，配合定时任务能力使用，本 Skill 只负责单次执行
