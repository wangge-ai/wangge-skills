# 电商利润数据分析工作流

这是一套通用流程，用来把后台导出的表格和人工维护表，整理成一份可对账、可分析、可展示的经营数据工作台。

## 流程总览

```text
后台/RPA 下载数据
        ↓
AI 扫描文件夹并识别报表类型
        ↓
清洗成标准明细
        ↓
按业务公式重算字段
        ↓
和旧 Excel / 旧报表对账
        ↓
生成汇总表、图表和工作台
        ↓
沉淀成下次可复用的 Skill / 工作流
```

## 第一步：数据下载

后台登录、账号切换、验证码和风控，建议继续用 RPA 或人工处理。

AI 更适合从“文件已经下载好”之后开始接手。把下载文件放在固定文件夹里，每次分析只告诉 AI 文件夹路径。

## 第二步：识别报表

不要只按文件名判断。

让 AI 同时看这些信息：

- 文件名
- 工作表名称
- 表头字段
- 日期范围
- 行数
- 关键字段是否存在

同一类后台导出，不同批次也可能列位置不一样，所以优先按表头字段定位，不要按固定列号读取。

## 第三步：清洗标准明细

标准明细建议至少包含：

- 日期
- 平台
- 店铺
- 运营
- SKU / 商品 ID
- 商品名或品牌
- 数量
- 销售额或出库货值
- 成本
- 推广费
- 补单金额
- 扣点
- 运费
- 佣金
- 利润

SKU、商品 ID、订单号这类字段必须按文本处理。长数字一旦被 Excel 变成科学计数法，后面的匹配就会错。

## 第四步：重算公式

不要默认利润公式。

常见公式可以写成：

```text
利润 = 销售额
     - 商品成本
     - 推广费
     - 补单金额
     - 平台扣点
     - 税费
     - 财务成本
     - 佣金
     - 运费
     + 补单商品成本
```

但这只是示例。真实项目里，要以你公司原来的 Excel 口径为准。

## 第五步：对账

对账至少分三类：

- 旧表有，新流程没有。
- 新流程有，旧表没有。
- 两边都有，但金额或数量不同。

不要把所有差异都当成错误。有时差异说明旧流程漏了一个数据源，有时是当前下载文件夹多了真实有效数据。

## 第六步：生成工作台

对账能解释之后，再做展示。

工作台可以包含：

- 总览指标
- 每日趋势
- 店铺排行
- 运营排行
- 利润率分析
- 推广费占比
- 亏损明细
- 新增/缺失数据说明
- 标准明细筛选

表格尽量单独展开，不要把多个大表挤在一行。数据分析页面最怕看起来很热闹，但读者找不到结论。

## 第七步：沉淀成工作流

第一次跑通之后，把这些东西固定下来：

- 文件夹扫描规则
- 报表识别规则
- 标准字段表
- 利润公式
- 对账口径
- 常见踩坑
- 输出文件清单

这样下个月只要换一批数据，AI 就能按同一套流程继续跑。
