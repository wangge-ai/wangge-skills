# 日志、错误码与验收证据规范

## 适用范围

本规范用于设计、评审和交接 RPA 流程的可观测性与验收证据。目标是让一次运行能够被定位、复核和安全交接，同时避免日志、状态文件或交付材料泄露凭据与业务身份信息。

本规范不替代具体平台的节点配置说明。平台操作方式应放在对应适配器中，业务字段则由项目自己的数据契约定义。

## 安全日志原则

1. **使用字段白名单。** 只记录排障和验收需要的字段；不要先完整记录对象再做脱敏。
2. **默认使用结构化单行日志。** 推荐 JSON Lines；若平台只能打印文本，则使用固定的 `key=value` 顺序并转义换行。
3. **用不透明标识关联。** 账号、店铺、客户等主体只写稳定的内部 ID、带密钥的摘要或映射后的序号。不要使用可被字典反推的裸哈希。
4. **分离机器字段与人类说明。** `status`、`event`、`error_code` 必须稳定；`message` 仅作已脱敏的补充说明，不能参与自动判断。
5. **限制动态内容。** 错误详情应去除换行、查询参数、页面正文和凭据，限制最大长度；原始异常仅进入受控诊断环境。
6. **统一时间语义。** 时间使用 ISO 8601 并包含时区；日期区间明确是闭区间还是查询端点的开区间。

### 推荐字段

| 字段 | 含义 | 约束 |
|---|---|---|
| `ts` | 事件发生时间 | ISO 8601，包含时区 |
| `level` | 日志级别 | `INFO`、`WARN`、`ERROR` |
| `run_id` | 本次流程运行 ID | 每次启动唯一 |
| `job_id` | 可独立重跑的任务 ID | 同一任务的日志、状态和产物一致 |
| `batch_id` | 批次或调度批次 ID | 可选；不得包含业务名称 |
| `pass_no` | 当前补跑轮次 | 正整数 |
| `item_index` | 当前处理项序号 | 使用序号或不透明 ID |
| `schedule_mode` | 日期或调度模式 | 使用稳定枚举值 |
| `date_start` | 业务开始日期 | `YYYY-MM-DD` |
| `date_end_inclusive` | 业务结束日期 | 明确为闭区间 |
| `query_end_exclusive` | 页面查询结束端点 | 若平台使用开区间则记录 |
| `stage` | 当前阶段 | 例如 `login`、`query`、`export`、`download`、`archive` |
| `event` | 发生的事件 | 稳定枚举，不写自然语言句子 |
| `status` | 任务状态 | 使用统一大小写和固定枚举 |
| `attempt` | 当前阶段尝试次数 | 从 1 开始 |
| `duration_ms` | 阶段耗时 | 非负整数 |
| `error_code` | 稳定错误码 | 成功事件留空 |
| `retryable` | 是否允许自动重试 | 布尔值；由错误码策略决定 |
| `artifact_id` | 产物或清单标识 | 不使用含个人目录的绝对路径 |
| `artifact_size` | 产物字节数 | 可选；非负整数 |
| `artifact_hash` | 产物摘要 | 可选；用于验收，不代表内容安全 |
| `message` | 已脱敏说明 | 可选、单行、限长 |

建议状态枚举为 `started`、`running`、`skipped`、`success`、`no_data`、`failed`。项目若已有状态枚举，可以保留，但必须在同一流程内保持拼写和终态语义一致。

### 禁止记录

- 用户名、真实账号名、真实店铺名、密码、验证码、Cookie、令牌、密钥、手机号或身份证件信息。
- 浏览器存储、请求头、完整 URL 查询串、整页 HTML、DOM 快照或未脱敏页面正文。
- 含 Windows 用户目录、网络共享凭据或客户目录结构的绝对路径。
- 原始表格内容、订单内容或可以重建业务身份的文件名。
- 未经检查的截图。确需保留截图时，应先遮盖敏感区域并受控存放，不把二进制或 Base64 写入日志。

安全示例：

```json
{"ts":"2026-08-10T08:00:01+08:00","level":"INFO","run_id":"run-7f2c","job_id":"job-03","pass_no":1,"item_index":3,"stage":"download","event":"download_complete","status":"running","artifact_id":"artifact-21","artifact_size":20480}
```

## 稳定错误码

错误码用于程序分支、重试策略和验收汇总。错误文本可以调整，错误码的含义不可随文案变化。

### 命名与演进规则

- 优先沿用项目现有的稳定约定；新项目使用小写 ASCII `snake_case`，例如 `login_timeout`。
- 错误码不得拼接日期、序号、文件名或异常文本。
- 一个错误码只表达一种可操作原因；需要改变含义时新增错误码。
- 维护错误码目录的版本和废弃记录，不复用已废弃代码。
- `no_data`、`skipped` 属于业务结果，不应伪装成错误。
- 进程退出码与业务错误码分离：退出码只表示命令是否成功执行，详细原因由 `error_code` 表达。

### 基础错误码目录

| 错误码 | 含义 | 默认处置 |
|---|---|---|
| `config_invalid` | 必填配置缺失或格式错误 | 停止，人工修正 |
| `date_mode_invalid` | 日期模式不受支持 | 停止，人工修正 |
| `date_range_empty` | 计算得到不可导出的空区间 | 跳过或改用适用模式 |
| `login_required` | 当前会话需要重新登录 | 转人工或受控重登 |
| `captcha_detected` | 检测到验证码或滑块 | 使用获准方式、转人工或失败跳过 |
| `page_timeout` | 页面在时限内未进入目标状态 | 有上限地重试 |
| `element_not_found` | 目标元素在当前页面不可用 | 刷新证据后有上限地重试 |
| `export_trigger_failed` | 导出动作未成功触发 | 有上限地重试 |
| `download_timeout` | 未在时限内发现完成下载 | 有上限地重试 |
| `download_incomplete` | 发现临时文件或文件仍在变化 | 等待或重试，禁止归档 |
| `artifact_invalid` | 文件为空、格式错误或与任务不匹配 | 隔离产物并重试 |
| `archive_failed` | 产物移动、改名或登记失败 | 保留源文件并重试 |
| `state_read_failed` | 状态文件不可读或结构不兼容 | 停止，保护现场 |
| `state_write_failed` | 检查点无法原子写入 | 停止，避免重复执行 |
| `unexpected` | 未分类异常 | 保留脱敏上下文，转人工 |

项目可以扩展目录，但应同时定义：触发条件、是否可重试、最大重试次数、退避方式、终态映射和人工接管条件。

## 日志、状态、产物三证验收

验收必须通过同一个 `run_id` 和 `job_id` 将三类证据关联起来。

### 证据一：日志

- 有运行开始、关键阶段、最终结果事件，时间顺序合理。
- 每次重试都有 `attempt` 或 `pass_no`，不能覆盖前一次失败证据。
- 失败事件包含稳定 `error_code`，成功事件不残留旧错误码。
- 日志通过敏感信息检查，且不存在未受控的异常堆栈或页面正文。

### 证据二：状态

- 状态使用原子写入或等效机制，不留下半写文件。
- 保存任务身份、当前阶段、尝试次数、更新时间和最终状态。
- `success` 与 `no_data` 等终态的跳过规则明确；可重试失败不得误标为完成。
- 状态版本可识别；不兼容版本应明确报错，不能静默重置。

### 证据三：产物或产物清单

- 成功任务存在与 `job_id` 对应的最终文件，且扩展名、大小、修改时间和命名规则正确。
- 文件不带下载临时后缀，大小在稳定观察周期内不再变化，必要时能够被目标解析器打开。
- 产物目录不存在同名静默覆盖；重名策略有确定的后缀或版本号。
- `no_data` 使用产物清单记录 `artifact_count=0` 和判定依据；不能简单用“目录里没有文件”证明无数据。
- `skipped` 应指向此前已经验收通过的状态和产物清单。

### 结果判定

| 结果 | 日志证据 | 状态证据 | 产物证据 | 是否通过 |
|---|---|---|---|---|
| `success` | 完整且无未处理错误 | 终态为成功 | 最终文件验证通过 | 三项一致才通过 |
| `no_data` | 有明确无数据判定事件 | 终态为无数据 | 清单明确记录零产物 | 三项一致才通过 |
| `skipped` | 有跳过原因和引用 | 指向既有终态 | 既有产物或零产物清单仍有效 | 引用可追溯才通过 |
| `failed` | 有错误码和最后阶段 | 非成功终态 | 无最终产物，或异常文件已隔离 | 作为失败场景验收通过 |

出现以下任一冲突时不得判定成功：日志成功但状态未落盘、状态成功但文件缺失、文件存在但仍是临时下载、产物日期与任务日期不一致、失败后遗留文件被误当成新产物。

## 场景矩阵

每个项目至少执行以下矩阵；不适用项需要写明理由，不能直接删除。

| 场景 | 关键操作 | 预期日志 | 预期状态 | 预期产物/清单 |
|---|---|---|---|---|
| 正常有数据 | 完成查询、导出、下载和归档 | 完整阶段链，最终 `success` | 成功终态 | 一个可验证最终文件 |
| 正常无数据 | 页面明确显示无结果 | `no_data` 判定事件 | 无数据终态 | 零产物清单 |
| 已完成任务再次运行 | 命中断点状态 | `skipped`，引用原任务 | 原终态不被覆盖 | 原产物仍可验证 |
| 首轮瞬时失败、补跑成功 | 注入一次可重试错误 | 先失败再重试成功，轮次可见 | 最终成功并保留尝试信息 | 只接纳最终有效产物 |
| 登录失效 | 使用过期会话 | `login_required` | 非成功终态 | 无最终产物 |
| 验证码或滑块 | 进入验证页面 | `captcha_detected` | 可人工接管或有限补跑的失败状态 | 无最终产物 |
| 页面或元素超时 | 让目标状态超时 | 稳定错误码和有限重试 | 不误标成功 | 无最终产物 |
| 下载超时或未完成 | 保留临时下载状态 | `download_timeout` 或 `download_incomplete` | 非成功终态 | 临时文件不进入最终目录 |
| 产物格式异常 | 提供空文件或错误格式 | `artifact_invalid` | 非成功终态 | 异常文件隔离 |
| 重名归档 | 预置同名文件 | 记录确定的冲突处理 | 成功或明确失败 | 旧文件不被静默覆盖 |
| 状态写入中断 | 模拟落盘失败 | `state_write_failed` | 不生成虚假终态 | 已下载文件保留待核对 |
| 进程中断后恢复 | 在中间阶段终止再启动 | 新旧运行 ID 可关联 | 从允许的检查点恢复 | 不重复接纳同一产物 |
| 普通调度日 | 只运行每日任务 | 调度决策可追溯 | 每个任务独立状态 | 每个任务独立清单 |
| 周一非月初 | 每日任务加本月累计 | 顺序与任务 ID 明确 | 两个任务互不覆盖 | 两份独立证据 |
| 每月十日 | 每日任务加上月全月 | 顺序与任务 ID 明确 | 两个任务互不覆盖 | 两份独立证据 |
| 周一且十日 | 每日、本月累计、上月全月 | 三个任务顺序明确 | 三个任务互不覆盖 | 三份独立证据 |
| 周一且月初一日 | 跳过空的本月累计 | 有明确跳过原因 | 不创建伪成功任务 | 仅存在适用任务证据 |

## 验收记录模板

```text
流程版本：

测试环境：
时区：
场景编号：
run_id / job_id：
日志证据位置：
状态证据位置：
产物或清单位置：
敏感信息检查：通过 / 不通过
三证一致性：通过 / 不通过
结论：通过 / 有条件通过 / 不通过
遗留问题与负责人：
```

## 交接要求

交接包至少包含：

1. 流程版本、变更摘要、适用范围和已知限制。
2. 入口参数、变量类型、默认值、日期边界和时区约定。
3. 状态机、终态与补跑规则，以及状态版本迁移方式。
4. 稳定错误码目录、重试上限、人工接管条件和恢复步骤。
5. 已脱敏的日志样例、状态样例和产物清单样例。
6. 场景矩阵执行结果，包含失败场景，而不只提供成功截图。
7. 平台版本、逐节点截图索引和所有尚未核对的版本差异。
8. 部署步骤、回滚步骤、依赖项、权限边界和定时触发说明。
9. 日常运行检查表：启动前检查、运行中观察点、结束后三证核对。

交接材料只能使用占位主体、序号或不透明 ID。测试数据应为合成数据；若必须使用生产证据，应先完成脱敏并限制访问范围。
