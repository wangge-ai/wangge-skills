# UI、登录、验证码、下载与资源清理

把每次 UI 操作设计成“动作 + 可验证结果 + 已知失败结果 + 超时闭环”，不要依赖固定等待和连续盲点。

## 1. 选择稳定元素

按优先级定位元素：

1. 稳定业务属性、可访问名称、角色和语义文本。
2. 稳定父容器与相对子元素关系。
3. 页面区域、iframe 或窗口句柄加语义属性。
4. 图像或坐标，仅作为最后手段并记录分辨率、缩放和窗口前置条件。

避免只使用动态 ID、易变 class、绝对 XPath、序号或屏幕坐标。元素在 iframe 内时，明确记录 iframe 层级；页面刷新、登录跳转或弹窗重建后重新捕获元素，不复用失效句柄。

根据截图给建议时标记置信度。没有节点配置、元素属性或运行证据时，不声称已确认精确定位方式。

## 2. 使用条件等待

为关键动作定义结果集合：

```text
执行动作
  ├─ 成功元素出现或旧元素消失 -> 继续
  ├─ 已知失败元素出现 -> 分类并闭环
  └─ 超时 -> 记录稳定错误码并闭环
```

遵守以下规则：

- 优先等待页面状态变化，不用长时间固定睡眠替代判断。
- 对短暂可选弹窗使用短超时并把异常输出设为 `False`，随后显式判断。
- 保存等待结果并实际使用；不要创建一个从未参与 IF 的输出变量。
- 统一布尔值。编辑器可能返回布尔或字符串时，先规范化，例如 `str(value).strip().lower()`。
- 成功条件和失败条件并行考虑。例如登录后既等待业务入口，也检测密码错误、验证码、短信验证和超时。
- 页面操作后重新验证目标状态，不以“点击指令没有报错”代表成功。

## 3. 处理动态页面和弹窗

把偶发 UI 分支放在其可能出现的动作之后，并保持局部：

1. 短等待检测弹窗或遮罩。
2. 可安全关闭时关闭并验证消失。
3. 需要业务判断时记录状态并退出当前业务项。
4. 关闭失败时记录清理错误，但不要覆盖原始业务错误。

不要无条件关闭未知弹窗。不要让一个业务项遗留的遮罩、页面或焦点影响下一业务项。

## 4. 分类登录结果

至少区分：

| 场景 | 建议状态 | 建议错误码 | 默认动作 |
|---|---|---|---|
| 密码或账号错误 | `credential_failed` | `credential_error` | 关闭页面；改变重试策略前确认 |
| 账号停用或权限不足 | `credential_failed` | `account_disabled` / `access_denied` | 关闭页面；不自动重复登录 |
| 登录页滑块未通过 | `captcha_failed` | `login_slider_failed` | 有限重试或留待批次补跑 |
| 短信、扫码或人工验证 | `login_failed` | `interactive_verification_required` | 按授权策略人工介入或跳过 |
| 登录成功元素超时 | `login_failed` | `login_timeout` | 关闭页面；有限补跑 |
| 未识别页面 | `failed` | `login_page_unexpected` | 保存脱敏证据并关闭页面 |

不要把所有登录问题统称为“元素找不到”。先检查已知错误元素，再把剩余情况归为稳定的超时或页面异常。

错误分支按顺序执行：

1. 打印安全日志，使用序号或脱敏标识。
2. 写入状态、阶段和错误码。
3. 关闭当前业务项页面。
4. 退出当前子流程或返回失败结果。
5. 由父级业务项循环继续下一项。

不要在子流程中误用会终止整批的退出指令。

## 5. 遵守验证码合法边界

只使用以下方式：

- 平台提供的官方验证或人工完成方式。
- 已获用户授权、符合平台条款和法律要求的验证码服务。
- 检测验证码、记录状态、关闭页面、有限补跑或等待人工处理。

禁止提供或实施：

- 绕过、破解或规避验证码与反自动化控制。
- 伪造设备、隐藏自动化特征或规避风控。
- 窃取会话、Token、Cookie 或复用未授权认证材料。
- 以坐标暴力拖动、无限刷新或无限重试对抗风控。

调用合法验证能力后，至少验证一项成功信号和一项失败信号：

- 滑块元素消失且登录成功元素出现，才视为成功。
- 滑块仍存在、失败提示出现或超时，标记 `captcha_failed`。
- 不因验证指令本身返回成功就假定页面已通过验证。

## 6. 设计下载闭环

按以下顺序执行：

1. 使用独立下载暂存目录，避免把旧文件误认为新文件。
2. 触发下载并优先接收下载节点返回的精确文件路径。
3. 等待临时扩展名消失、文件非空且大小稳定；必要时校验扩展名、文件头、工作表或结构。
4. 使用精确源路径归档，不用宽泛通配符猜测最新文件。
5. 按任务键生成确定性目标名；发生同名时使用明确覆盖、版本或后缀策略。
6. 验证归档目标真实存在且有效。
7. 归档验证成功后才写 `success`。

区分失败阶段：

- 查询明确显示无记录：`no_data`。
- 没看到下载按钮或按钮不可用：页面/元素失败。
- 已触发但未产生完整文件：`download_timeout` 或 `download_incomplete`。
- 源文件有效但移动、重命名或校验失败：`archive_failed`。

归档失败时保留有效源文件并记录路径，不删除可恢复证据。不要通过删除旧输出或状态来处理重跑。

## 7. 管理资源所有权

为每个业务项记录它创建的页面、窗口、临时文件和子进程。仅清理当前业务项拥有的资源，不关闭用户原有页面或其他并行业务项资源。

在正常、异常、验证码失败、提前退出和超时路径中统一执行清理：

- 关闭当前业务项页面和弹窗。
- 终止或释放当前业务项创建的子进程、句柄和会话。
- 处理未完成下载：隔离或保留诊断，不误删其他文件。
- 恢复必要的窗口焦点或浏览器上下文。
- 记录清理失败，但保留原始错误为主错误。

让父级流程负责批次级资源，让子流程负责自身创建的资源。必要时使用 `finally`、统一清理子流程或等价结构。

## 8. 配置错误处理

按错误作用域选择行为：

- 节点短暂异常：有限重试当前节点。
- 单业务项 UI、登录、下载异常：写状态、清理、退出子流程、继续父循环。
- 路径不可写、脚本缺失、状态结构损坏等基础配置错误：停止整批，避免制造错误状态和重复产物。
- 清理动作异常：忽略并继续清理其他资源，同时写安全日志。

不要把所有节点设为“忽略异常并继续执行”。忽略异常只负责不中断，不能替代状态写入、分支跳转和资源清理。

## 9. 验收清单

分别制造并验证：

- 正常登录和正常下载。
- 密码错误、账号停用、登录超时。
- 登录页和业务页验证码失败。
- 已授权验证成功后，滑块消失且目标页面出现。
- 动态弹窗出现与不出现。
- 无数据、下载超时、部分文件、归档失败。
- 页面关闭失败及下一业务项不受污染。
- 进程中断后陈旧页面、临时文件和 `running` 的恢复。

用运行日志、状态记录和实际产物共同验收；不要只看流程截图或节点绿色勾选。
