# 写作风格指南（Style Guide）

> Agent 在按 `outline.md` 填章时，必须遵循本指南。
> 目标：让小白看得懂、能动手、不被劝退。

## 1. 语气

- 中文 · 口语化 · 第二人称"你"
- 像同事讲解，不像产品说明书
- 不用"赋能 / 抓手 / 闭环 / 链路"等空泛词
- 不堆叠形容词

## 2. 段落

- **每段 ≤ 4 行**
- 超过 4 行立刻拆段或转成列表
- 段间空一行

## 3. 排版元素

| 元素                  | 用途                  |
| ------------------- | ------------------- |
| **加粗**              | 关键词、关键操作            |
| `行内代码`              | 文件名、路径、命令、参数        |
| 代码块                 | 配置、命令、模板（必标语言）      |
| 表格                  | 对比、参数、清单            |
| 引用块 `>`             | 提示、注意、补充            |
| 列表（- / 1.）          | ≥3 项的并列内容           |
| 分隔线 `---`           | 章节之间                |

## 4. Emoji 锚点

仅在以下场景使用，每段最多 1 个：

| Emoji | 含义     |
| ----- | ------ |
| 🎯    | 重点 / 目标 |
| 💡    | 小贴士     |
| ⚠️    | 警告 / 注意 |
| ✅     | 推荐做法    |
| ❌     | 反例 / 不要 |
| 📌    | 必须记住    |
| 📍    | 入口 / 位置 |
| 🔧    | 配置 / 工具 |

避免连续多个 emoji 堆砌。

## 5. 技术词的处理

- 每个技术词**第一次出现**时立刻给一句"人话解释"
- 示例："Skill（技能，本质上是一个 `.md` 文件，告诉 AI 该怎么干一类活）"

## 6. 步骤化操作

- 任何"操作类"内容必须用数字列表
- 每步以**动词**开头："点击 / 选择 / 填入 / 复制 / 重启"
- 关键按钮 / 菜单名用**加粗**
- 配套给"预期看到的现象"，例如"状态变为'已绑定'即成功"

## 7. 截图占位

- 凡是操作步骤都给一处截图占位：`[截图：xxx]`
- 命名规范：`[截图：模块-页面-动作]`，如 `[截图：设置-API-填写Key]`

## 8. 引用与出处

- 引用第三方文章必须给链接
- 文末参考资料表：标题 + 链接 + 平台 + 日期

## 9. 安全脱敏

- API Key / Token 全部用 `sk-xxxxxx` `your-token-here` 占位
- 真实手机号 / 微信号 / 工号 全部用 `13xxxxxxxxx` `xxx@xxx`
- 不暴露任何作者的真实账号信息

## 10. 字数与节奏

- 目标字数：5000–10000（中文字符）
- 章节分布建议：
  - 第 0–3 章合计约 25%
  - 第 4–6 章约 35%（核心使用）
  - 第 7–8 章约 20%
  - 第 9–10 章 + 附录约 20%
- 单章不超过总字数的 25%

## 11. 结尾

- 用"3 段学习路径"收尾（第 1 天 → 第 1 周 → 第 1 月）
- 一句话总结鼓励

## 12. HTML 报告交付

- 默认同步生成独立 HTML 报告，文件名与 Markdown 同名，仅扩展名不同
- HTML 报告用于本地预览、打包和分享，不等于公众号内联 HTML
- 报告必须包含首屏视觉锚点、目录、章节锚点、代码块样式、表格层级和移动端适配
- 默认使用暖色编辑教程版式：深色渐变首屏、暖砂纸面、分层表格、章节色条
- 不再使用旧的蓝白系统文档配色；不要回退到 `#f6f7fb` 背景、纯白主卡片、单一蓝色强调的简版排版
- Markdown 中的原始 HTML 必须被转义，不能执行 `<script>` 等标签

## 13. 命中即拒（绝不出现）

- ❌ 编造未经验证的"功能 / 价格 / 入口"
- ❌ 把营销话术直接抄进教程
- ❌ 长段无小标题
- ❌ 中英文混杂不留空格
- ❌ "众所周知 / 想必大家都知道 / 不用多说" 等弱化表达
