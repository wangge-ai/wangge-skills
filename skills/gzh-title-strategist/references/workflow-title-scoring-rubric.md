# Title Scoring Rubric

Use 7 checks, 1 point each.

| Check | Pass condition | Repair move |
|---|---|---|
| 明确实体 | Title names a concrete object such as 公众号、商品链接、评论、GitHub、Skill、Codex、后台数据 | Add the object readers can picture |
| 真实任务 | Title contains an action such as 输入、生成、拆解、复盘、评分、筛选、搭建 | Replace vague description with a task verb |
| 可交付结果 | Title promises 报告、表、清单、公式、SOP、工作流、教程、模板 | Add the artifact readers get |
| 一眼知道拿走什么 | Reader can infer the takeaway within one glance | Move the output/result into the title |
| 工具没有压过业务结果 | Tool name supports the result instead of becoming the whole title | Put the business output after the tool |
| 推荐流陌生人能看懂 | A cold reader can understand the task without private context | Remove internal shorthand and vague hype |
| 首屏有图可证明 | The promise can be shown with screenshot, table, chart, cover, or workflow image | Choose a title that can be visually evidenced |

## Strong Patterns

- `输入公众号后台数据，自动生成选题复盘报告`
- `我拆了 48 篇文章，整理出一套公众号标题评分表`
- `从0开始搭一套公众号数据复盘工作流（附标题评分表）`
- `别急着让 AI 写全文，先用这 7 条规则筛标题`

## Weak Patterns

- `分享一个 AI 工具`
- `这个工具太强了`
- `AI 写作又升级了`
- `标题优化方法论`

Weak titles usually fail because they do not name the object, task, or deliverable.
