# 公众号转小红书 V2

把长文改造成一条能在手机上快速理解、值得收藏、证据可信的小红书笔记。转换不是摘要：先选择一个读者任务，再重排证据和阅读顺序。

默认账号方向是 **目标公众号 · 实战证据编辑部**：真实任务、可见结果和可复用资产优先。视觉母版必须根据内容类型、真实素材和已核验的小红书样本路线选择；不得把某套网页 UI 主题、米白手账风或固定品牌色直接当成所有笔记的默认答案。

## 按任务读取

- 批量筛文章、判断适不适合转或材料是否齐全：读 [references/eligibility-and-routing.md](references/eligibility-and-routing.md)。
- 转换单篇、拆系列、写逐页脚本或发布文案：读 [references/conversion-workflow.md](references/conversion-workflow.md)。
- 设计封面、卡片、图片方案或审美系统：读 [references/visual-system.md](references/visual-system.md)。
- 制作 HTML、导出 PNG 或交付发布包：读 [references/render-and-qa.md](references/render-and-qa.md)。
- 使用原图、裁切截图或用户要求高清时：读 [references/real-assets-and-hd.md](references/real-assets-and-hd.md)，核对素材身份与有效像素，不能只检查画布尺寸。

若任务涉及对比、流程、矩阵、路线图或决策树，使用 `article-visual-trigger`。只有确实缺少非证据型位图素材时才使用 `imagegen`；生成图不能冒充产品界面、测试结果、用户评价或作者现场。创建或修改 HTML/CSS 时使用 `frontend-design-system`。

## 三种工作模式

### 1. 文章库筛选

用户给文件夹或选题库时，先去重同一文章的 Markdown、HTML、MHTML 等载体，再按文章而不是文件计数。全量扫描标题、正文结构、图片引用和可见产物；只对高分候选深读和目视检查。

交付候选清单、推荐批次、推荐切口、内容路由、可复用证据和缺失素材。不要为每篇直接生成卡片。

### 2. 转换方案

用户只要判断、标题、脚本或视觉方案时，停在文字交付。至少给出：适配结论、单一读者任务、标题路线、封面路线、逐页任务、证据来源、需补素材和发布文案草稿。

### 3. 可上传发布包

用户明确要求直接转换、生成图片或完成发布包时，默认交付：

```text
<topic>/
  内容脚本.md
  index.html
  publish.html
  png/
    <series>-01.png ...
  发布文案.md
  source-map.md
  image-manifest.json
  项目说明.md
```

卡片默认统一 3:4，标准 PNG 为 1080×1440。用户要求高清时，另交付原生渲染的 2160×2880 至 `png-hd/`，保留标准版；不把小图放大称为恢复高清。具体上传限制按实际发布入口核验。页数由内容和证据决定，通常 5–9 张；不要为了凑页或压页损害阅读。

`index.html` 保存排版源稿；`publish.html` 是按顺序看图、查看原图、复制推荐标题与正文的本地入口。普通图文发布使用图片、标题、正文和话题，不把HTML当成上传格式，不把内部说明混入待复制正文。用户只要脚本或少量素材时不必制作完整入口。

## 先过适配门，再开始改写

每篇文章先判为四级之一：

- `A / ready`：任务明确，有可见结果或可保存资产，证据足够，可直接转换。
- `B / ready-with-assets`：内容成立，但缺关键截图、结果图或授权素材；先列补图清单，也可用明确标注的设计卡完成低承诺版本。
- `C / re-angle`：主题有价值但过宽、过时或公众号味重；先缩成一个切口或拆成系列。
- `D / hold`：主要是二手汇编、泛观点、时效已失效或强结论无证据；本轮不建议转。

评分和批量筛选字段见 `eligibility-and-routing.md`。分数帮助排序，不替代用户明确选择，也不能把缺失数据当零价值。

## 核心工作流

### 1. 完整阅读，建立证据地图

提取一条主任务、一个可带走结果、作者动作、原始截图/图片、数据、失败、限制和时效信息。删除公众号关注引导、重复背景、二维码说明和与主任务无关的章节。

先建立 `claim → evidence → page`：强结论没有证据时降级为个人判断、问题或删除。时效性工具信息、价格、规则和功能在发布前核验。

### 2. 选择一个内容路由

- **教程 / SOP**：入口、关键动作、可见验收、常见错误、可保存清单。
- **成果 / 案例**：任务、输入、结果、关键选择、复用方法、边界。
- **对比 / 选型**：同一任务、统一口径、差异证据、分场景建议。
- **诊断 / 避坑**：失败症状、原因证据、最短修复、修复后验证。
- **清单 / 资源**：选择标准、分组、用途、获取与使用条件。
- **观点 / 热点**：一个冲突、一个事实支点、一个本地场景、一个可执行动作。

一条笔记只走一条主路由。文章存在两个独立的强结果时，拆成系列，不把所有章节塞进一组图。

### 3. 选择发布目标

标题、封面和页面顺序同时服务一个主目标：

- `search`：对象或工具 + 任务，承接明确搜索需求。
- `save`：教程、步骤、清单、模板或判断表，强调可带走资产。
- `discussion`：有证据的冲突、误区或阶段判断，留下可回答的问题。
- `trust`：真实过程、失败边界、人工复核和作者选择，建立账号可信度。

可以有次目标，但不能让四种目标同时抢封面。

### 4. 设计最小可信证据包

默认由四种页面角色组合，不固定顺序和数量：

1. `cover`：对象、任务或冲突；一秒识别主题。
2. `proof`：真实结果、界面、原文、数据或失败状态；前两页至少出现一项。
3. `delivery`：步骤、清单、Prompt、判断表或工作流；让读者能保存和执行。
4. `boundary`：适用条件、不能做什么、人工复核或下一步。

每页只完成一个信息动作。正文长段必须重写为标题、短解释和视觉证据，不能靠缩小字号塞入。

### 5. 选择视觉模型

优先选择与证据匹配的一种：

- `proof-led`：真实截图或结果占主视觉，适合教程、案例、避坑。
- `human-led`：作者/使用现场 + 大字判断，适合复盘、观点和信任型内容；只能用有权使用的真人素材。
- `information-led`：清单、步骤、流程或对比主导，适合可保存资产；仍需在前两页放真实证据锚点。

默认不使用抽象机器人、发光芯片、紫蓝渐变和泛科技城市作为 AI 内容主视觉。它们不能证明任务发生过。

视觉模型确定后，继续在 `visual-system.md` 中选择一条样本支持的封面路线。教程/SOP 默认优先高对比教程型、白底工具清单型或截图结果型；低饱和大留白只适用于一句话观点，不得用于需要强调步骤、结果和收藏价值的实操内容。

### 6. 写标题、Caption 和标签

标题优先说明对象、任务与结果，分别准备搜索型、收藏型、冲突型候选，再推荐一条。数字、完整、实测、免费、自动、Skill、SOP、资料包都必须有可指认载体。

Caption 使用真实场景钩子、图片未展开的判断、一个限制和一个自然互动问题；不要逐页复述。标签覆盖工具、角色、场景和问题，不借无关热点。

### 7. 制作与验证

先完成封面和信息最复杂的一页，再批量生成其余页面。检查真实素材来源、裁切后的有效像素、相对路径、文字边界、图片裁切、手机缩略图、上传顺序和清单约定尺寸。高清版需在100%查看关键图片细节；程序尺寸通过不等于审美或内容获用户确认。不要在画面上堆报告页脚、复杂导航和无意义页码。

## 账号表达

- 像一个正在电商与内容一线做事的人，把任务、结果、选择和限制摊开讲。
- 第一人称只用于作者确实做过、看过或判断过的事；Agent 执行不能自动改写成作者亲测。
- 保留具体对象：商品、SKU、评价、图片、Excel、报告、工作流、SOP、Skill 和人工复核。
- 少用“炸裂、颠覆、秒杀、普通人必须”等无证据压力词；可以有明确判断，但要说明条件。

## 完成标准

- 这条笔记只解决一个读者问题，并有明确发布目标。
- 封面在 25% 缩略图下仍能识别对象和任务，不依赖装饰理解。
- 封面不是报告首页：不得出现细小报告页脚、装饰性页码、空占画面的巨大数字或无意义中段留白。
- 前两页至少出现一个真实证据锚点；没有证据时承诺已经降级。
- 每页只有一个结论或动作，图片承担证明或教学作用，不是填空。
- 页数由内容决定；没有固定六页、固定素材比例或全页同模板。
- 原始事实、作者判断、外部资料、生成素材和待补截图边界清楚。
- 发布文案不重复全部卡片，限制、标签和图片顺序可直接使用。
- 标准版与高清版分别符合清单尺寸，无越界、丢图、错序和临时文件；真实来源、设计示意及生成素材身份可追溯。
- 分别记录技术验证、用户视觉确认和外部发布状态；不能把其中一项通过代替其余状态。
