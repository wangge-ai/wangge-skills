# Render And QA

## Canvas

- 标准：1080×1440 PNG，3:4。
- 高清交付：同一HTML源以原生2倍像素密度渲染2160×2880，分别放入 `png-hd/` 与 `png/`。不是将已模糊PNG插值放大；先按 `real-assets-and-hd.md` 检查素材有效分辨率。
- 同一笔记所有图片使用同一比例。
- HTML 卡片的文字用系统可用中文字体，避免依赖未安装的网络字体。
- 图片用相对路径；交付包移动后仍应加载。
- 页数由脚本和 `image-manifest.json` 驱动，通常 5–9 张，不写死为 6。

## Export sequence

1. 先渲染封面和信息密度最高的一张内容页。
2. 在真实 3:4 画布检查字重、行距、图片裁切和页脚。
3. 批量渲染。
4. 验证每张文件的像素尺寸。
5. 程序检查文字元素是否越过卡片边界。
6. 人工抽查封面、最复杂的表格页和最后一页。

## When the preview viewport is shorter than 1440

某些应用内浏览器的可截图区域会比设定画布少一段顶部 UI 高度。症状是 PNG 高度不足或页脚消失。

不要直接截成 1080×1356，也不要裁掉页脚。

优先使用能容纳完整卡片的浏览器截图或元素截图，并通过设备像素密度导出；不要以屏幕可见区高度限制原生导出。仅在环境确实不支持时采用以下保全内容的标准版回退，明确这是重采样，不能称作原生高清：

1. 计算可见高度 `H`。
2. 用 `scale = H / 1440` 等比缩放整张卡。
3. 新宽度为 `1080 × scale`，截图区域仍保持 3:4。
4. 以高质量 Bicubic/Lanczos 重采样到 1080×1440。
5. 再检查页脚和最小字号。

例如可见高度 1356 时，缩放比例为 `0.9416667`，截图区域为 1017×1356，再输出为 1080×1440。

## Visual QA

- 25% 缩略图下能读懂封面主题。
- 封面有一个明确焦点，不同时抢标题、拼贴、标签和装饰。
- 每页只有一个主结论。
- 表格列宽足够，中文不挤成单字换行。
- 原图里的重要对象没有被 `object-fit: cover` 裁掉。
- 正文、页码、账号名、来源说明均在安全区。
- 深色页对比度足够；浅灰说明字在手机上仍可读。
- 前两页至少有一个证据锚点；没有真实证据时封面承诺已经降级。
- 长截图已经裁成可读区域，没有整条缩小塞入画布。

## Evidence QA

- 原始实测图没有被重做后冒充原图。
- 比较表中的结论有作者限定或来源。
- 团队效率、金额、时间等数据保留 `体感/约/样本范围`。
- AI 生成素材不承担事实证据。

## Final file QA

- 区分封面大字与发布标题：交付一条推荐发布标题、3～5条备选、纯正文和话题；记录实际字符数，注明计数方式。
- 交付说明区分上传PNG、复制文字、HTML源稿与本地预览入口；现有文件已经齐全时直接提供入口，不让用户重新回忆交付物。
- 平台数字限制随发布入口变化。需要宣称当前上限时核对官方资料或用户所用编辑器；未核验时使用保守文案长度并说明未核验，不把第三方旧限制写成平台事实。
- 检查预览页图片切换、复制成功或选中文字的回退、移动端溢出，以及本地图片加载；不得由预览按钮触发未授权发布。

- 逐张检查清单约定尺寸：标准版 `1080x1440`，高清版 `2160x2880`，两套顺序和内容一致。
- 100%查看封面和关键证据裁切：文字、产品细节、图表标签是否确实可读；尺寸正确不能掩盖低清素材。
- 文件名按上传顺序补零：`01`、`02`……
- HTML 打开后图片无 404。
- PNG 数量与 manifest 一致。
- `source-map.md` 中每张图都有来源、处理方式和证据用途。
- 没有测试图、临时文件、低清缩略图混入发布目录。
