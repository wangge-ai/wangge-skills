# 单篇转换流程

## 1. 清理来源

删除公众号阅读器提示、关注引导、二维码、作者卡、重复标题、评论区导出和无关推荐。保留作者动作、工具入口、步骤、失败、限定语、来源链接、原图与图片附近的解释。

先把工具版本、价格、平台规则、免费额度和“最新”类信息列为时效项；发布前核验，无法核验就删除时效承诺或改成文章原始时间口径。

## 2. 写一条读者任务

回答：`读者看完这组图，马上能完成、避免或判断什么？`

答案包含两个独立动词时，优先拆成两条。公众号背景、完整长 Prompt 和延伸讨论可以进入 Caption、置顶评论或公众号完整版，不必塞入卡片。

## 3. 建立 claim–evidence–page 表

改编完成后再对照原文检查内容覆盖：哪些保留、哪些有意舍弃、哪些影响读者复用且需要补充。不要把“核过数字与截图”称为完整性核对。教程中的输入字段、操作前提、混合样本或重复计数口径、可复制Prompt及附件是否实际随包提供，往往不能只靠截图概览交代。可把长Prompt放本地补充文件，但需说明读者在平台上是否实际能取得；不要为追求完整把整篇长文重新塞入图片。

| Claim | Evidence | Confidence | Page role |
|---|---|---|---|
| 要表达的结论 | 原图、截图、作者动作、数据或外部来源 | 事实 / 个人判断 / 推断 | cover / proof / delivery / boundary |

强结论无证据时只能降级为个人阶段判断、待验证问题或删除。`existing-proof` 不得重绘后冒充原图；生成素材只能做氛围或示意。

## 4. 六条内容路由

下面是推荐阅读顺序，不是固定模板。页面可合并或展开，通常 5–9 张。

### 教程 / SOP

任务结果封面 → 完成后的可见产物 → 前置条件/入口 → 3～5 个关键动作 → 一页常见错误 → 可保存核对表 → 适用边界。

### 成果 / 案例

结果封面 → 输入与任务 → 结果全貌 → 关键选择或转折 → 可复用方法 → 人工复核 → 当前边界。

### 对比 / 选型

同一任务封面 → 测试输入与口径 → 方案 A/B 的真实结果 → 差异批注 → 分场景选择 → 一个反例 → 决策表。

没有统一输入和真实输出时，不写成“实测排名”；改成基于公开资料的任务适配整理。

### 诊断 / 避坑

失败症状封面 → 错误证据 → 根因拆分 → 最短修复 → 修复后验证 → 预防清单 → 不适用条件。

### 清单 / 资源

读者任务封面 → 选择标准 → 按场景分组 → 每项只讲用途和限制 → 上手顺序 → 获取/授权条件 → 收藏核对表。

### 观点 / 热点

一个冲突封面 → 原始事实或事件 → 作者为什么改变判断 → 电商/内容本地场景 → 反例或限制 → 今天能做的一步。

## 5. 页面规格

每页记录：

```markdown
### 03 / 页面名称
- 角色：cover / proof / delivery / boundary
- 目的：
- 主标题：
- 辅助文字：
- 视觉结构：
- 资产：existing-proof / designed-card / generated-asset / screenshot-needed
- 证据与来源：
- 文件名：topic-03.png
```

一页一个结论或动作；主标题尽量可独立理解，辅助文字只解释证据。截图必须说明它教读者看哪个位置、做哪个动作或判断什么。

## 6. 标题与封面承诺

分别准备三路候选：

- 搜索型：对象/工具 + 具体任务；
- 收藏型：步骤/清单/SOP + 可带走结果；
- 冲突型：误区/失败/阶段判断 + 证据对象。

从对象、输入、任务、结果四项里至少选三项。产品名可以前置，但不能替代任务。数字、完整、实测、自动、免费、Skill、SOP 和资料包都要在页面或附件中对账。

目标公众号的已验证亲历教程，优先考虑用户偏好的“我用 + 具体工具 + 真实任务/输入 + 结果”句式；例如我用WorkBuddy拆550条商品评论，找到3类需求。保留用户指定的工具名称。若完整标题不适合实际入口长度，给出短标题备选，由封面承接结果；未核对入口时不把字符估算当平台审核结论。

封面主标题通常控制在 8～14 个汉字；工具名、数字或对象可做独立标签。需要更长信息时分成主标题和一行副标题，不缩成小字段落。

## 7. Caption

1. 真实场景或测试动机，1～2 个短段；
2. 图片没有展开的关键判断，2～4 个短段；
3. 一个限制、失败条件或人工复核点；
4. 一个读者能回答的互动问题或自然承接。

Caption 不逐页复述，也不新增图片里没有证据的强结论。标题准备 3～5 个，推荐 1 个；标签通常 5～10 个，覆盖工具、角色、场景与问题。

## 8. 来源清单

`source-map.md` 至少记录每张图的原始文件、裁切或批注、结论用途、是否生成、是否待补和使用边界。`image-manifest.json` 记录顺序、文件名、尺寸、页面角色和资产类型。

## 常见失败

- 把公众号小标题逐个变成卡片：重新选择单一任务和阅读顺序。
- 固定六页或固定素材比例：按证据链增减页面。
- 每页同一圆角模板：只复用字体、色板、批注和署名规则。
- 封面只写工具名：补任务或结果对象。
- 第一页漂亮、第二页才开始长背景：把证据或交付物提到前两页。
- 没有真实失败图却做前后对比：改为错误/解法示意并标注来源边界。
- 只有功能目录或泛科技图：补共同任务、实际输出和可保存资产，否则降级。
