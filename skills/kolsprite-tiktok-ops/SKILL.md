# TikTok 自动运营工作流

把 TikTok 运营里反复、耗时的工作（选品、找店、拆视频、筛达人、建联、定计划）变成一句自然语言指令。本技能负责提供"查询顺序 + 筛选逻辑 + 证据要求 + 输出格式"，数据由达人精灵 MCP 提供。

## 前置条件（必须先行检查）

1. 检查达人精灵 MCP 是否已连接：当前会话中应存在以下可调用工具（名称以实际 schema 为准，服务前缀可能不同）：
   - 统一 MCP（1 个服务，5 个工具）：`kolsprite_creator_search`、`kolsprite_video_search`、`kolsprite_product_search`、`kolsprite_shop_search`、`kolsprite_caption_extract_url`
2. 若工具不可用，先明确告知用户需要配置达人精灵 MCP（统一服务地址 `https://mcp.kolsprite.com/mcp` 与 secret-key 鉴权方式见 `references/安装配置指南.md`），并给出配置步骤，不继续执行。
3. 提醒用户：MCP Key 与 API Key 是两套独立凭证，不能混用；真实 Key 只保存在本地配置，不写入任何文档或截图。

## 通用执行规则（所有工作流适用）

1. **结果前置**：先输出核心结论，再展开数据依据，最后给行动建议。
2. **数据可溯源**：每条关键结论标注数据来源（商品/店铺/视频/达人）、统计周期（近 7 天/近 30 天/总量）、地区与货币单位。
3. **区分事实与判断**：明确区分"查询到的数据"（观察）、"基于数据的推断"（推断）、"无法证实的猜测"（假设），不得混为一谈。
4. **不编造数据**：MCP 查不到、字段缺失或数据不足时，如实写"数据不足"，说明缺什么、为什么缺，并给出获取途径，禁止用估算值或编造值填补。
5. **分页与限额**：单次请求 `pageNum × pageSize` 不得超过 1000；数据量大时分批查询并注明只展示 Top N。
6. **输出可执行**：每个工作流结尾必须给出"下一步做什么"，以动词开头（如：跟进、验证、邀约、测试），并标明优先级。
7. **只问关键问题**：若缺失信息会改变主要结论，一次只问一个最关键的问题；其余缺失信息按合理默认值处理并标注。

## 工作流一：选品 → 店铺 → 视频 → 达人 → 字幕 → 行动方案（完整闭环）

**触发指令示例**：用达人精灵查美国区美妆类目，价格 30–50 美元、评分 4.5+、近 7 天销量增长较快，跑完整个选品流程并给出 7 天执行方案。

**执行顺序**（严格按此顺序推进，每步输出后继续下一步）：

1. **选品**：调用 `kolsprite_product_search`，按用户给定的国家、类目、价格、评分、销量条件查询。**注意：当前该接口传销量相关 `order_field`（如 `sales_volume`、`sales_volume_gr7d`、`sales_volume_lst30d` 等）会触发服务端 500，因此默认不传 `order_field`，使用服务端默认排序；如需自定义排序，先尝试 `rating`、`reviews`、`videos`、`influencers`。**输出：商品名、价格、评分、近 7 天/30 天销量与销售额、增长率、链接。标注统计周期。
2. **标杆店铺**：从候选商品提取店铺，调用 `kolsprite_shop_search` 或商品返回的店铺字段，找销量较高、评分达标的店铺。**注意：`shop_search` 同样存在销量排序字段触发 500 的问题，默认不传 `order_field`，使用服务端默认排序；如需自定义排序可尝试 `rating`。**输出：店铺名、评分、在售商品数、近 30 天销量/销售额、带货达人数、链接。
3. **带货视频**：对重点商品调用 `kolsprite_video_search`，筛选近 30 天销售额靠前的视频。输出：视频链接、达人、发布时间、播放量、互动率、销量、销售额。
4. **达人筛选**：从视频反查达人，调用 `kolsprite_creator_search` 或视频返回的达人字段，按成交表现排序。输出：达人主页、粉丝数、平均播放、互动率、带货销量/销售额、GPM（若有）、合作优先级（高/中/低）。
5. **字幕拆解**：对表现最好的 1–3 条视频调用 `kolsprite_caption_extract_url`，按"工作流五"的拆解模板输出。
6. **行动方案**：综合以上证据，输出：值得跟进的商品清单（含理由）、对应标杆店铺、内容方向（3 个可复用的 Hook）、达人合作优先级清单、未来 7 天每日执行计划（动词开头，可执行）。

## 工作流二：竞品账号诊断

**触发指令示例**：分析这个公开 TikTok 账号，找出内容支柱、爆款公式和未来 7 天改进动作。

**执行要求**：
1. 输入为公开 TikTok 账号链接或昵称，先用 `kolsprite_creator_search`（search_type=N 昵称）查询达人档案。**注意：`video_search` 不支持按达人筛选（无达人 ID 参数）**，内容维度改用"该达人带货品类关键词"搜索（如账号主打假发就搜 `wig`），并结合达人档案中的内容分类推断内容支柱，标注证据来源（账号档案 / 品类内容生态）。
2. 公开数据不足时，按规则尝试读取公开主页与视频页；若遇到登录、验证码、地域限制或反爬，停止并说明原因，不以搜索摘要冒充真实数据。
3. 输出结构（结果前置）：
   - 账号定位与目标用户（推断，标注依据）
   - 内容支柱：账号在做什么内容、哪些是主线
   - 爆款视频结构：共同使用的开头钩子、卖点、演示方式
   - 更新节奏：发布频率、稳定与否
   - 当前问题：定位模糊、更新不稳、互动低等（有数据则标注）
   - 可复制的结构（哪些值得借鉴、哪些不能直接照搬）
   - 未来 7 天三个动作（动词开头，按优先级排序）

## 工作流三：新类目进入研究

**触发指令示例**：研究美国区宠物用品类目，判断是否值得进入，给出差异化定位和前三个验证动作。

**执行要求**：
1. 从商品、店铺、内容、达人四个维度收集证据：
   - 商品：类目商品数、价格带分布、销量/销售额 Top、集中度
   - 店铺：主要玩家、店铺评分与服务指标（24 小时回复率、发货率）
   - 内容：带货视频数量、播放与互动水平、常见内容主题
   - 达人：达人数量、带货能力分布、是否容易找到合作资源
   - 若 `product_search`/`shop_search` 返回 500：先检查是否传了销量相关 `order_field`；若是，去掉 `order_field` 重试。仍失败则降级用 `video_search` 嵌套的商品/达人数据补齐商品与店铺证据，并在报告中标注"接口异常、数据降级"。
2. 输出结构（结果前置）：
   - 是否建议进入（建议/暂缓/先小范围验证 + 一句话理由）
   - 最值得关注的价格带与细分方向
   - 竞争是否过热（依据：商品数、集中度、内容饱和度）
   - 差异化定位建议
   - 前三个验证动作（每个动作写明验证什么、怎么做、判断标准）
3. 证据不足时，明确列出缺失信息与获取途径，不强行下结论。

## 工作流四：30 天增长计划

**触发指令示例**：分析这个账号是否适合做美国区家居类目，生成从定位、内容到达人合作的 30 天计划。

**执行要求**：
1. 同时评估"账号现有能力"与"目标类目机会"，不孤立看粉丝数。
2. 输出结构（结果前置）：
   - 适配度结论：建议进入/暂缓/先小范围验证 + 理由
   - 内容调整：保留、停止、新增三类内容清单
   - 定位调整建议
   - 三条可选增长路径（每条写明适用条件与预期）
   - 30 天行动计划：按周划分（第 1 周验证、第 2–3 周放量、第 4 周复盘），每步动词开头
3. 商业目标不明时，默认按"商品销售"目标规划，并注明假设。

## 工作流五：视频字幕拆解与脚本生成

**触发指令示例**：提取这个 TikTok 视频的字幕，拆解脚本结构并生成可复用的新脚本。

**执行要求**：
1. 调用 `kolsprite_caption_extract_url` 提取字幕。**链接格式**：分享短链（`https://vm.tiktok.com/xxxxx` 或 `https://vt.tiktok.com/xxxxx`）与网页版复制的长链（`https://www.tiktok.com/@账号/video/视频ID?...`）均可解析（2026-08-18 实测长链正常）。若报"当前不支持该URL解析"，先让用户从 TikTok App"分享→复制链接"取短链重试。
2. 若返回"当前不支持该URL解析"或提取失败，说明链接格式不兼容或该视频无字幕/无权限；如实告知用户，并给出替代方案（用视频标题、封面文字、评论高频词做内容推断，标注为"非字幕证据"）。
3. 提取成功后先输出原文，再输出中文字幕（保留带时间戳版本供深度拆解）。
4. 按以下结构拆解：
   - 开头钩子（前 3 秒说了什么、为什么能留住人）
   - 用户痛点（视频对准了谁的什么问题）
   - 核心卖点（产品/内容的关键承诺）
   - 证明或演示方式（如何让观众相信）
   - 结尾行动号召（CTA）
5. 生成"可复用但不直接照搬"的脚本结构：提炼公式（如：痛点开场 → 演示 → 对比 → 促单），并基于原结构生成 1 个新脚本，替换具体内容。
6. 明确告知：仿写不等于搬运，提醒用户注意平台原创规则。

## 输出格式总约定

- 结论先行，证据随后，行动收尾。
- 列表用项目符号，关键数字加粗。
- 每个结果块标注：数据来源、统计周期、地区、货币、是否完整。
- 方案类输出结尾附"风险与假设"一行：列出哪些结论依赖假设，哪些数据缺失。

## 常见问题与边界

- 商品/店铺接口 500：`product_search`/`shop_search` 在传入销量相关 `order_field`（如 `sales_volume`、`sales_volume_gr7d`、`sales_volume_lst30d`、`sales`、`sales_lst7d`、`sales_lst30d`）时会触发服务端 500（2026-08-18 已复现）。**解决方案：默认不传 `order_field`，使用服务端默认排序**；若需排序，可尝试 `rating`、`reviews`、`videos`、`influencers`（`product_search`）或 `rating`（`shop_search`）。仍失败则重试一次或稍后再试；商品维度可降级使用 `video_search` 结果中嵌套的 product 对象，并在报告中标注"接口异常、数据降级"。
- 达人类目筛选：`creator_search` 的 `product_category_list` 传英文类目名可能返回 0 条（参数暂不生效）；keyword 参数匹配的是达人昵称/简介而非类目。需要按类目找达人时，优先从 `video_search` 结果的达人字段提取，或直接搜已知达人昵称。
- **窄粉丝区间（如 1–10 万粉）下 `creator_search` 关键词搜索退化（2026-08-18 实测）**：`keyword=makeup/skincare/beauty`（search_type=K）+ `fans_cnt_from/to` 过滤，三次返回同一批综合热门榜（total=10000、每页 20 条完全一致、去重后仅 20 人），带货类目混杂服装/健康品/家居，垂直度极低——这是接口限制而非查询错误，不要反复换词重试。**可靠的垂直达人反查路径：`video_search` 按品类关键词（如 makeup、skincare）扫带货视频 → 每条含作者昵称/fansCnt/带货数据 → 提取 1–10 万粉作者 → 用 `creator_search`（search_type=N）昵称核验完整档案（GPM/邮箱/带货类目/互动率）**。注意「beauty routine」这类泛词返回的视频垂直度偏低，优先用 makeup/skincare 等精准词。
- 查询无结果：调整筛选条件（放宽价格/评分/时间窗口）或更换关键词后重试，仍无结果则如实说明，不编造。
- 数据量大：取 Top 20 展示，提示可用分页继续查看。
- 无字幕视频或链接格式不兼容：说明无法提取字幕（2026-08-18 实测长链/短链均可解析；若仍报错优先让用户从 App 复制短链重试），改用视频描述、封面文字或评论高频词分析（标注为推断）。
- 合规边界：不做任何绕过平台限制、抓取私密数据的操作；遇到验证码/地域限制/反爬即停止并说明。
