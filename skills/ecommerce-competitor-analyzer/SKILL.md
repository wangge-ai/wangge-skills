# 电商竞品与数据分析

## 核心原则

先检查证据，再选择分析模块。商品链接只是线索，不等于已获得实时销量、完整评论、私域流量或历史价格；任何结论都要标明来源、采集时间、样本量和字段状态。

## 能做什么

- 分析用户提供的商品表、截图、保存页面、评论数据和已有采集清单。
- 比较商品定位、价格带、规格、卖点、信任证据、评价主题和页面表达。
- 对提供的历史快照做价格变化、排名变化或监测候选分析。
- 生成结构化 JSON、Markdown 和独立 HTML 报告。

## 数据路线

有结构化表格时优先运行：

```powershell
python scripts/analyze_ecommerce_dataset.py --input "<数据文件>" --out "<分析报告.md>" --category "<类目>"
```

有竞品清单时可运行：

```powershell
python scripts/analyze_competitors.py --input "<竞品数据>" --out "<竞品报告.md>" --json-out "<事实包.json>" --category "<类目>"
```

需要验证链接可达性时，使用 `scripts/probe_product_links.py`；需要报告时使用 `scripts/render_report_html.py`。先查看各脚本 `--help`，不要猜参数。

本 Skill 本身不是登录态爬虫，也不随附 Kimi WebBridge。若用户只给商品链接，可使用分享包外已授权的可见浏览器工具采集页面证据；无法进入、需要登录或字段不可见时，应标为受阻或未知。

## 实时平台选择与登录门槛

- 实时采集前必须让用户明确选择本次平台；选择结果就是本次报告的平台分母，不默认扩展为“全平台”。只有用户明确选择全部支持平台时，才逐项执行全部平台。
- 保存的 HTML、CSV、JSON 或既有采集清单属于本地证据分析，不要求重新登录，也不重复抓取。
- 对实时链接或平台搜索，先让用户确认已在可见浏览器完成所选平台登录。这个确认表示可以开始检查，不等于每个平台网页都必须显示昵称；用户不登录时，说明只能获得有限公开信息、无法完整采集搜索结果、评价、问大家、SKU 或销量字段。
- 逐个平台独立做最小业务可用性预检：在任务自有标签打开目标搜索页、商品页或登录后的业务入口，并立即核对当前 URL、平台域名、标题和正文。首页没有昵称、个人中心或订单入口，不能单独作为未登录证据；拼多多桌面首页尤其可能不展示身份。
- 标签页指针、当前 URL 或平台域名不一致属于线路错误，不属于登录失败。先在任务自有标签重新导航并复核，限定重试后仍错位时切换其他已授权线路或把该平台写为 `not_available`。
- 只有业务页明确出现登录、扫码、验证码、滑块或风控拦截时，该平台才写 `waiting_login`。可继续的平台立即进入业务采集；某个平台等待登录不得阻断其他平台。
- 没有任何平台可继续且至少一个平台等待登录时，整体才写 `waiting_login`。至少一个平台取得有效样本、其他平台等待登录时，整体写 `partial`，并保留已完成平台的竞品池、价格带、卖点和证据。
- 不索要或输出账号、密码、Cookie、Token；不自动登录，不绕过验证码或风控。

## 分析流程

1. 建立证据清单：来源、时间、平台、样本量、字段覆盖率和失败项。
   - 只展开用户本次明确选择的平台；用户给出的单个平台链接只是种子证据，不代表可以自行加入其他平台。
   - 从类目、品牌和竞品要求生成检索词，只在所选平台的已授权可见浏览器中采集；无需用户为每个已选平台预先提供商品链接。
   - 种子链接所属平台可继续时必须先读取种子商品，形成类目、品牌、核心卖点和检索词证据；不得因另一个平台等待登录而跳过种子商品。
   - 每个平台分别记录 `success / partial / waiting_login / needs_input / not_available / not_attempted`、有效样本数和受阻原因。有效样本为 0 时不得写 `partial`；未选择的平台不得混入覆盖率或完成分母。
2. 统一商品、价格、销量、评价、规格和时间口径，区分展示价、活动价、SKU 价与结算价。
   - 搜索结果中的“首单价”“补贴后”“优惠后”和未标注价分别保留，不能统称到手价。
   - “人收货”“人付款”“本月行业热销”等只作为页面销量展示原文，不换算真实成交量或销售额。
   - 广告样本与自然样本分别计数；页面顺序不能升级为官方榜单名次。
3. 选择与现有字段匹配的分析模块，不对缺失字段做推断。
4. 为结论绑定输入中的 `sample_id`；没有编号时使用稳定的 `ROW_###`，并将结果分成观察事实、基于样本的推断、运营建议和待验证问题。
5. 按 `references/report-template.md` 输出摘要、对比、机会、风险和下一步。

最终回复只保留一句话结论、最多 5 条关键结果、平台覆盖、最多 5 个主要产物和最多 3 条下一步；完整表格、证据和采集诊断写入报告，不在最终回复中平铺。

## 工作台实时市场证据合同

由工作台执行实时多平台市场分析时，只交付逐条事实和原始证据，不自行生成最终报告：

- 写入 `competitor_evidence.csv`，每条样本保留唯一 `sample_id`、平台、商品、展示价及口径、广告属性、来源 URL、采集时间、登录状态和 `raw_evidence_path`。
- 写入 `collection_evidence_manifest.json`，逐平台登记状态、样本编号和原始文件；原始页面证据统一放入 `evidence/raw/`。
- 写入 `analysis_notes.json`，观察、机会、建议和限制必须通过 `evidence_ids` 引用现有样本；不得在其中写总数、广告/自然数量、价格带或中位价。
- 不得由模型手工计算汇总数字；平台分母、广告/自然/未知数量、价格带和价格统计只由工作台确定性事实文件生成。
- 最终 `success` 由工作台确定性质量门决定；缺清单、缺原始证据、引用不存在或所选平台未覆盖时保留已采样本并降为 `partial`。
- 公开报告不得出现内部工具名称、调试过程或模型思索过程。

## 不能做什么

- 不绕过登录、验证码、风控、付费接口或平台访问限制。
- 不把页面展示的销量口径写成真实成交额，也不伪造搜索量、转化率或市场份额。
- 不声称正在持续监控，除非用户提供了真实的历史快照或已授权系统。
- 不把少量评论或个别竞品外推为全类目结论。
