# 电商排行主图样本采集

## 核心原则

只采集公开页面、用户提供的保存页面或明确授权的数据。页面没有可见排名信号时，不得称为“官方榜单”；销量排序搜索结果应明确标注为“销量排序搜索结果”。

## 能做什么

- 从公开榜单、搜索结果或保存的 HTML 中整理商品位置、标题、链接和主图。
- 下载主图、生成 `manifest.csv`、联系表、分析提示和独立 HTML 报告。
- 对来源受阻、图片失效、字段缺失和排序口径不明分别记录状态。

## 优先输入

用户最好提供平台、类目、目标数量、公开来源 URL、排序口径和采集日期。平台公共来源与限制见 `references/platform-public-sources.md`。

## 工具路线

有已保存 HTML 时，优先使用确定性脚本：

```powershell
python scripts/collect_main_images.py --html-dir "<保存页面目录>" --platform "<平台>" --category "<类目>" --out "<输出目录>"
```

已通过授权浏览器取得结构化商品卡片时，把浏览器导出的 JSON 交给同一确定性脚本，不让模型重新抄写清单：

```powershell
python scripts/collect_main_images.py --structured-json "<浏览器导出.json>" --platform "<平台>" --category "<类目>" --out "<输出目录>"
```

结构化记录至少要同时具备商品身份（`item_id` 或 `item_url`）、标题和主图 URL。只有 logo、骨架屏、横幅或没有商品身份的图片不算成功样本；没有有效商品样本时脚本必须返回失败。

已有图片和表格时，可补建清单与报告：

```powershell
python scripts/build_sample_manifest.py --input "<素材目录>" --output "<输出目录>"
python scripts/build_main_image_report.py --manifest "<manifest.csv>" --out "<report.html>"
```

这些脚本不随附 Kimi WebBridge。分享包可以分析公开 URL、保存的 HTML 或使用者主动导出的结构化 JSON；若网站必须登录、出现验证码或要求使用现有 Chrome 登录态，应停下并让使用者选择已授权浏览器工具，不绕过限制。

在完整工作台环境中，采集前要评估三条线路：本地文件或静态公开页优先脚本；用户 Chrome 已有合规登录态时优先 Kimi WebBridge；公开动态页且已有匹配、已授权的 BrowserAct 浏览器时可使用 BrowserAct。最优线路拿不到有效商品证据就切换下一条，不得借用无关浏览器配置、自动登录或绕过验证。

## 实时平台与登录门槛

- 实时榜单或搜索采集前必须让用户明确选择一个平台；不默认使用“全平台”，也不因类目相同自行追加其他平台。
- 保存 HTML 或已授权浏览器导出的结构化 JSON 是本地证据，可以直接进入确定性脚本，不要求重新登录。
- 实时页面开始业务采集前，先做最小业务可用性预检：在任务自有标签打开目标榜单或搜索页，立即核对当前 URL、平台域名、标题、正文和商品卡。用户未登录或不愿登录时，应说明公开信息有限。
- 用户已经确认登录准备后，不能只因首页没有昵称、个人中心或订单入口就判定未登录；目标页可访问且没有明确登录/验证墙时继续采集，并把身份显示状态如实写入证据。
- 标签页指针、当前 URL 或平台域名不一致属于线路错误，不属于登录失败；重新导航并复核，仍错位时切换已授权线路或写 `not_available`。
- 只有目标页明确出现登录、扫码、验证码、滑块或风控时才返回 `waiting_login`，不得继续抓登录页。
- 预检通过后若采集中再次出现验证码、重新登录或风控，只保留阻塞证据并暂停该平台，等待用户完成验证后从新输出目录重跑。
- 不索要账号、密码、Cookie 或 Token，不自动登录，不绕过验证。

## 工作流程

1. 核对用户选择的平台、来源是否公开、排序信号是否可见、目标数量是否合理；实时来源先完成登录预检。
2. 保存来源 URL、页面标题、采集时间和可见排序依据。
3. 采集商品卡片与主图，商品身份以稳定链接或商品 ID 为主；“人付款”“人收货”“本月行业热销”等页面文案只能作为可选销量/热度信号，不能作为识别商品卡的唯一条件。
4. 去重后保留原始页面位置，并将广告位与自然位分开统计，不把补位样本、广告或个性化推荐伪装成原排名。
5. 运行清单与报告脚本，检查每张图能否打开、商品与图片是否对应。
6. 汇总完成、部分完成、受阻和未知项，说明真实分母。
   - 有效商品样本为 0 时只能写 `waiting_login / needs_input / failed` 等真实状态，不能写 `partial`。

## 作为实时市场分析的上游

当工作台把本 Skill 用作实时市场样本来源时，在原有图片清单之外同步交付机器可核验的市场证据：

- 写入 `competitor_evidence.csv` 和 `collection_evidence_manifest.json`，把商品卡原始导出、页面截图或结构化快照放入 `evidence/raw/`；每条样本的 `raw_evidence_path` 必须能实际打开。
- 需要定性观察时写入 `analysis_notes.json`，每条只引用现有样本编号。
- 不得由模型手工计算汇总数字；广告/自然/未知分母、价格带和平台数量交给工作台确定性事实文件。
- 最终 `success` 由工作台确定性质量门决定；图片下载成功或进程退出正常不能单独升级状态。
- 公开报告不得出现内部工具名称、调试过程或模型思索过程。

## 不能做什么

- 不使用私有 Cookie、验证码破解、隐蔽反检测或未经授权的付费接口。
- 不承诺淘宝、京东、拼多多或抖音公共页长期稳定；页面结构和风控会变化。
- 不把搜索结果位置、广告位或个性化推荐写成官方销量排名。
- 不负责图片视觉诊断；采集完成后应交给主图诊断或视觉反向拆解 Skill。
