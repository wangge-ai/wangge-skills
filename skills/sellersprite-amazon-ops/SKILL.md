# 亚马逊选品上架全链路

把亚马逊运营里反复、耗时的工作（选品、竞品拆解、词库搭建、Listing 与广告方案）变成一句自然语言指令。本技能负责提供"查询顺序 + 筛选标准 + 输出格式"，数据由卖家精灵 MCP 提供。

## 前置条件（必须先行检查）

1. 检查卖家精灵 MCP 是否已连接：当前会话中应存在以下可调用工具（名称以实际 schema 为准，服务前缀可能不同）：
   - 关键词市场/选品：`sellersprite_keyword_research`、`sellersprite_keyword_miner`
   - 关键词趋势：`sellersprite_keyword_research_trends`、`sellersprite_aba_research_trend`
   - ASIN 与竞品：`sellersprite_asin_detail`、`sellersprite_asin_competitor`、`sellersprite_asin_prediction`
   - 流量与转化：`sellersprite_traffic_keyword`、`sellersprite_traffic_keyword_stat`、`sellersprite_keyword_order`、`sellersprite_keyword_conversion`
2. 若工具不可用，先明确告知用户需要配置卖家精灵 MCP（服务地址 `https://mcp.sellersprite.com/mcp`、连接类型 streamable-http、Header `secret-key` 鉴权，详见 `references/安装配置指南.md`），并给出配置步骤，不继续执行。
3. 提醒用户：MCP Key 与 API Key 是两套独立凭证，不能混用；真实 Key 只保存在本地配置，不写入任何文档或截图。

## 通用执行规则（所有工作流适用）

1. **结果前置**：先输出核心结论，再展开数据依据，最后给行动建议。
2. **数据可溯源**：每条关键结论标注数据来源（关键词市场 / 竞品分析 / 流量反查 / 转化分析）、统计周期（如 2026-07 月度、近 30 天、90 天窗口）、站点（如 Amazon US）。
3. **区分事实与判断**：明确区分"查询到的数据"（观察）、"基于数据的推断"（推断）、"无法证实的猜测"（假设），不得混为一谈。
4. **不编造数据**：MCP 查不到、字段缺失或数据不足时，如实写"数据不足"，说明缺什么、为什么缺，并给出获取途径，禁止用估算值或编造值填补。
5. **排序字段枚举限制**：卖家精灵工具的排序字段（order.field）是枚举值，只能传工具说明中列出的字段，禁止猜测其他字段；不确定时用"按搜索量列出"这类自然语言描述，让 AI 自选合法排序。
6. **选品判断三件套**：判断市场机会以「购买率 + 供需比 + 点击集中度」为主，不要依赖"增长率"排序——增长率高的词很多是从 0 起量的异常词，可能虚高数千倍，不可作为选品依据。
7. **输出可执行**：每个工作流结尾必须给出"下一步做什么"，以动词开头（如：上架、验证、投放、跟款），并标明优先级。
8. **只问关键问题**：若缺失信息会改变主要结论，一次只问一个最关键的问题；其余缺失信息按合理默认值处理并标注假设。

## 工作流一：市场机会判定（数据选品）

**触发指令示例**：用卖家精灵 MCP 研究美国站&lt;宠物用品&gt;的关键词市场，找出月搜索量高、购买率高、点击集中度低（不被头部垄断）的机会词，告诉我哪个方向最值得做。

**执行顺序**（严格按此顺序推进，每步输出后继续下一步）：

1. **机会词扫描**：调用 `sellersprite_keyword_research`（关键词市场/选品）或 `sellersprite_keyword_miner`（关键词挖掘）。**不要直接丢一个泛词（如 dog、toys）让它扩展，返回相关性不稳定**；用筛选器组合（minSearches 搜索量下限、minPurchaseRate 购买率下限、maxMonopolyClickRate 点击集中度上限、minSearchNearlyCr 近 3 个月增长率下限）扫描机会词。输出每个机会词：月搜索量、购买率、商品数、PPC 竞价、供需比、点击集中度。
2. **产品方向识别**：把机会词映射到产品方向，从「需求体量、竞争分散度、广告成本、复购属性」四个维度比较，给出最值得做的方向及理由。
3. **趋势验证**：对入选方向的核心词调用 `sellersprite_keyword_research_trends`（关键词趋势）拉取月度数据（搜索量/购买量/购买率/同比/环比），判断市场处于上升期还是萎缩期；若萎缩，用 `sellersprite_keyword_miner` 找替代方向（如供需比高、头部未垄断的细分词）。
4. **进场结论**：综合输出值得进的方向（或暂缓 + 替代方向）、机会点、风险提示。

**输出结构**（结果前置）：
- 机会词榜单（表格：关键词/搜索量/购买率/商品数/PPC/供需比/点击集中度/机会判定）
- 首选方向 + 理由（需求/竞争/广告/复购四维）
- 趋势判断（上升/萎缩/企稳，附关键数字）
- 进场结论 + 切入方式（选品方向、定价、运营节奏）

## 工作流二：竞品拆解（跟谁打、怎么打）

**触发指令示例**：用卖家精灵 MCP 分析美国站&lt;B00CPDWT2M&gt;的竞品，整理成表格并总结价格带和打法；再反查它的流量结构和转化结构。

**执行顺序**：

1. **竞品定位**：调用 `sellersprite_asin_competitor` 以种子 ASIN 获取相关竞品，再用 `sellersprite_asin_detail`（或商品列表）核实月销、月销售额、类目排名。输出：竞品对比表（品牌/价格/评分/评论/月销/月销售额/类目排名/卖家来源）、价格带分析、头部玩家打法标签。
2. **单 ASIN 深度拆解**：调用 `sellersprite_asin_detail`（详情）+ `sellersprite_asin_prediction`（销量预测）。输出：价格（含历史区间）、评分/评论数、类目与排名、变体数量、Listing 质量分、认证标识、完整标题（逐词展示）、五点卖点（逐条拆解撰写逻辑：卖点类型/关键词埋点/说服手法）、图片/A+ 策略，以及"为什么卖得好"的多维分析（关键词布局、差异化卖点、评分评论、定价策略、类目竞争格局、变体覆盖、品牌背书）。
3. **流量反查**：调用 `sellersprite_traffic_keyword`（流量词明细）反查竞品流量来源词，按搜索量降序，输出每个词的月搜索量、购买率、自然排名、广告排名、PPC、流量占比；再调用 `sellersprite_traffic_keyword_stat`（流量结构概览）输出自然/广告/官方推荐词数量与占比，判断"自然流量健康型"还是"广告堆量型"，给出置信度与判断依据。
4. **转化结构诊断**：调用 `sellersprite_keyword_order`（反查模式 reverseType=W/M）反查近 30 天关键词转化结构，按转化优质词（E）/平稳词（S）/流失词（L）/无效曝光词（I）四分类，重点详列优质词与流失词（含转化率、曝光量、点击率），给出扩词/否词/降价建议。
5. **竞争策略结论**：综合输出是否值得跟头部正面竞争（依据评论护城河、价格带、流量结构）、对标谁（头部霸主 or 腰部玩家）、差异化切入点。

**输出结构**（结果前置）：
- 竞品对比表 + 价格带 + 打法标签
- 头部单 ASIN 画像 + "为什么卖得好"
- 流量结构（自然 vs 广告占比 + 健康度判断）
- 转化四分类 + 扩词/否词/降价建议
- 竞争策略结论（跟谁打、怎么打）

## 工作流三：词库搭建（从词根到可运营词库）

**触发指令示例**：用卖家精灵 MCP 基于核心词&lt;indestructible dog toy&gt;挖掘相关关键词，整理成词库，区分 Listing 埋词和广告投放用途。

**执行要求**：

1. **关键词挖掘**：调用 `sellersprite_keyword_miner`（keyword=词根，扩展查询）挖掘相关词；对已明确的目标词可用 keywordList 精准批量查询。输出每个词：搜索量、购买率、竞争度（SPR）、相关度。
2. **分类与筛选**：按长尾词/场景词/品类词三类分类；按搜索量降序；筛出"推荐词"（高相关 + 竞争适中 + 搜索量达标且有商业价值）。
3. **用途划分**：明确区分 Listing 埋词（高相关，适合标题/五点/描述）与广告投放词（搜索量和购买率俱佳，适合 Sponsored Products 投放）；两者皆宜的标注并说明理由。
4. **高转化词识别**：调用 `sellersprite_keyword_conversion`（90 天窗口，输出可能很大需先落盘再解析）筛出搜索量大、搜索转化率高、PPC 合理的词，按搜索转化率降序，标注 SEO/PPC 推荐用途。
5. **输出词库**：表格（序号/关键词/分类/搜索量/购买率/竞争度/相关度/推荐用途/备注）+ 词库使用建议总结。

**输出结构**（结果前置）：
- 推荐词库（核心/长尾/场景分级，带全部指标）
- 用途划分（Listing 埋词 / 广告投放 / 两者均可）
- 高价值转化词表（按搜索转化率降序）
- 词库使用建议（埋词位置、投放分层）

## 工作流四：从选品到上架全链路（完整闭环）

**触发指令示例**：请用卖家精灵 MCP 对亚马逊&lt;狗狗耐咬玩具&gt;细分类目完成一轮从选品到上架的完整调研：选品 → 竞品 → 词库 → Listing 方案。

**执行要求**：按顺序执行工作流一 → 二 → 三，最后补上方案生成：

1. **第一阶段（市场机会判定）**：按工作流一执行，用关键词市场筛选高搜索量+高购买率+低垄断的机会型关键词，明确产品定位。
2. **第二阶段（竞品分析）**：按工作流二执行，找出头部 Top 10-20 竞品，分析价格带、评价结构、上架时长、核心卖点、推广打法，给出定价与竞争策略建议。
3. **第三阶段（词库搭建）**：按工作流三执行，反查头部竞品的流量词与转化词结构，区分核心/长尾/场景/关联词，构建完整可落地词库。
4. **第四阶段（Listing 与广告方案）**：基于前三阶段数据生成：
   - Listing 标题：按"品类词 → 人群词 → 尺寸词 → 材质卖点 → 场景词 → 规格词"顺序，核心词前置前 80 字符
   - 五点卖点：每点写清卖点类型 + 关键词埋点 + 说服手法
   - 分层广告投放词表：精准匹配（购买率 >20% 的钻石词）→ 词组匹配（高转化中长尾）→ 广泛匹配（核心词根拓词）；附否词建议（购买率 <1% 的词直接否定）
5. **报告收尾**：给出"从数据到方案"总结——做什么（产品定位/定价）、跟谁打（对标对象）、怎么打（标题/五点/广告三层）、风险与假设。

## 输出格式总约定

- 结论先行，证据随后，行动收尾。
- 列表用项目符号，关键数字加粗。
- 每个结果块标注：数据来源、统计周期、站点、货币、是否完整。
- 方案类输出结尾附"风险与假设"一行：列出哪些结论依赖假设，哪些数据缺失。

## 常见问题与边界

- **排序字段枚举限制**：所有工具的 order.field 只接受工具说明列出的枚举值，传其他值会报错（2026-08-20 实测）。不确定时不要指定字段，用"按搜索量列出"这类自然语言描述。
- **增长率异常词**：keyword_research 按增长率（searches_growth）排序会返回从 0 起量的异常词（实测出现过 9000% 虚高），这类词购买率/商品数/均价异常，不可作为选品依据。选品判断以「购买率 + 供需比 + 点击集中度」三件套为主。
- **泛词研究相关性不稳**：直接传泛词（如 dog、toys）给 keyword_research/keyword_miner 扩展，返回相关性不稳定；用筛选器组合（minSearches + minPurchaseRate + maxMonopolyClickRate + minSearchNearlyCr）或 keyword_miner 的 keywordList 精准查询效果更稳。
- **keyword_miner 两种查询模式**：keyword（扩展查询，返回该词及相关词）用于挖词库；keywordList（精准查询，只返回传入词）用于选品对比。两者用途不同，不要混用。
- **keyword_order 参数**：必须传 reverseType（W=周 / M=月）和对应格式的 date（W 传 yyyyMMdd 且为当周周六，M 传 yyyyMM）；conversionType 可选（E 优质 / S 平稳 / L 流失 / I 无效曝光）。
- **traffic_keyword 明细**：需 asin + marketplace；size 控制返回条数，数据大时取 Top N 并注明；trafficKeywordTypes（primary 主要流量词 / precise 精准流量词）与 conversionKeywordTypes（excellent / stable / lost / invalid）用于分类筛选。
- **keyword_conversion 输出可能很大**（90 天窗口实测单次 350KB+），先落盘再解析，避免截断丢数据。
- **查询无结果**：调整筛选条件（放宽搜索量/购买率阈值）后重试；仍无结果如实说明，不编造。
- **数据量大**：取 Top 20-30 展示，提示可用分页继续查看。
- **合规边界**：只查询公开可查的数据；不做绕过平台限制的操作；数据缺失如实标注并给出获取途径。
