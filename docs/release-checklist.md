# 轻量发布检查表

这份检查表只用于“代码或资料将要公开”以及“正式版本发布”边界，不要求每次本地编辑都执行完整审计。

## 1. 公开范围

- [ ] 确认目标仓库、分支和可见性，未把私有或开发中仓库误设为公开。
- [ ] 只包含计划发布的源码、文档和脱敏示例；无压缩包、安装程序、浏览器配置和原始业务资料。
- [ ] 第三方代码、图片、模板和数据的来源与许可证允许当前发布方式。

## 2. 敏感信息

- [ ] 扫描当前文件和全部可达 Git 历史中的 Token、Cookie、密码、邮箱、手机号与本地绝对路径。
- [ ] 检查截图、图片元数据、日志、CSV/JSON 示例和生成文件中的个人或业务信息。
- [ ] 如果发现真实凭证，先撤销或轮换；仅删除当前文件不能清除历史副本。

## 3. 行为审查

- [ ] 列出所有联网、读取、写入、下载、删除、登录、浏览器和系统命令行为。
- [ ] 联网脚本限制到文档声明的公开目标，并拒绝本机、内网、保留地址和内嵌凭证。
- [ ] 输出只写入用户明确指定的位置，不静默删除或上传本地数据。
- [ ] 登录、验证码和访问控制遵循官方流程，不包含绕过逻辑。

## 4. 安装与运行

- [ ] 从远端做一次干净克隆，不依赖开发机工作区里的未跟踪文件。
- [ ] 把每个 Skill 复制到临时 Skills 目录并运行结构校验。
- [ ] 运行所有单元测试；对每个可执行脚本至少验证 `--help`，并为主要输入路径运行最小样例。
- [ ] 安装说明同时覆盖 macOS/Linux 和 Windows，依赖及最低 Python 版本写清楚。

## 5. 文档与许可

- [ ] `README.md`、`SKILL.md`、`agents/openai.yaml`、`skills.json` 的名称、用途和行为一致。
- [ ] 所有相对链接均可解析，引用的脚本、参考资料和示例真实存在。
- [ ] 每个正式 Skill 有 README 和许可证，仓库根许可证说明适用范围。
- [ ] 重新查看最终 diff，确认没有调试输出、特定客户名称或内部工作路径。

## 6. 发布后核验

- [ ] 推送后从未登录视角确认 README、许可证和目标文件可以访问。
- [ ] 查看 GitHub Security 页面中的 Secret Scanning、Dependabot 或 Code Scanning 提示。
- [ ] 记录本次验证日期、测试数量、已知限制和需要后续处理的问题。
